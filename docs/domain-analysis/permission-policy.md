# Boardly 권한 정책

## 개요
Boardly의 권한 시스템은 역할 기반 접근 제어(RBAC)를 기반으로 하며, 워크스페이스 단위로 권한이 관리됩니다. 보드는 공개 범위에 따라 접근 권한이 달라집니다.

## 권한 모델

### 워크스페이스 권한

#### 소유권과 권한의 분리
- **생성자**: Workspace 테이블의 `createdBy` 필드로 관리되는 생성자
- **권한**: WorkspaceMember 테이블의 `role` 필드로 관리되는 역할 기반 권한

#### ADMIN
워크스페이스의 관리자 역할로, 대부분의 권한을 가집니다.

**권한 목록:**
- 워크스페이스 설정 변경
- 멤버 초대/제거
- 멤버 역할 변경
- 모든 보드 생성/수정/삭제
- 모든 보드 멤버 관리
- 모든 카드 관리
- 모든 댓글 관리
- 워크스페이스 내 모든 보드에 대한 자동 접근 권한

#### MEMBER
워크스페이스의 일반 멤버 역할로, 제한된 권한을 가집니다.

**권한 목록:**
- 보드 생성/편집
- 카드 생성/편집/삭제
- 카드 이동
- 댓글 작성/수정/삭제
- 담당자 할당
- 워크스페이스 내 WORKSPACE 공개 보드에 대한 자동 접근 권한

#### 생성자의 특별 권한
워크스페이스 생성자(`createdBy`)는 ADMIN 권한과 함께 추가로 다음 권한을 가집니다:

**추가 권한 목록:**
- 워크스페이스 삭제
- 생성자 이전 (다른 ADMIN 멤버에게)

### 보드 권한

#### 보드 공개 범위
- **PRIVATE**: 보드에 직접 초대된 멤버만 접근 가능
- **WORKSPACE**: 워크스페이스 공개 - 해당 워크스페이스의 모든 멤버가 접근 가능
- **PUBLIC**: 전체 공개 - 링크를 가진 인터넷상의 모든 사용자가 접근 가능

**워크스페이스 타입별 보드 공개 범위:**
- **개인 워크스페이스**: PRIVATE, PUBLIC (WORKSPACE 옵션 없음)
- **팀 워크스페이스**: PRIVATE, WORKSPACE, PUBLIC (모든 옵션 사용 가능)

#### ADMIN
보드의 관리자 역할로, 모든 권한을 가집니다.

**권한 목록:**
- 보드 정보 수정/삭제
- 보드 멤버 초대/제거/역할 변경
- 보드 공개 범위 변경
- 모든 리스트 관리
- 모든 카드 관리
- 모든 댓글 관리
- 라벨 생성/수정/삭제
- 첨부파일 관리

#### MEMBER
보드의 편집자 역할로, 제한된 권한을 가집니다.

**권한 목록:**
- 보드 정보 수정
- 리스트 추가/수정/삭제
- 카드 생성/수정/삭제
- 카드 이동
- 댓글 작성/수정/삭제
- 담당자 할당
- 라벨 생성/수정
- 첨부파일 업로드/삭제

#### VIEWER
보드의 조회자 역할로, 읽기 전용 권한을 가집니다.

**권한 목록:**
- 보드 조회
- 리스트 조회
- 카드 내용 조회
- 댓글 조회
- 첨부파일 다운로드

#### PUBLIC_VIEWER (공개 보드 접근자)
PUBLIC 보드의 URL을 통해 접근한 사용자로, 읽기 전용 권한을 가집니다.

**권한 목록:**
- 보드 조회
- 리스트 조회
- 카드 내용 조회
- 댓글 조회
- 첨부파일 다운로드

## 권한 정책 규칙

### 1. 워크스페이스 권한 규칙
- 워크스페이스를 생성한 사용자는 자동으로 생성자(`createdBy`)가 되고 ADMIN 역할을 받는다
- 생성자는 워크스페이스에 대한 ADMIN 권한과 모든 보드에 대한 ADMIN 권한을 가진다
- 생성자는 생성자 이전을 통해 다른 ADMIN 멤버에게 생성자 권한을 이전할 수 있다
- 생성자 이전 후 이전 생성자는 새로운 역할(ADMIN/MEMBER)을 선택할 수 있다
- 동일한 사용자는 같은 워크스페이스 이름을 가질 수 없다
- 워크스페이스에는 최소 1명의 ADMIN이 있어야 한다
- 마지막 ADMIN의 역할을 MEMBER로 변경할 수 없다
- 생성자가 아닌 마지막 ADMIN은 자신의 역할을 변경할 수 없다
- 워크스페이스 ADMIN은 모든 보드의 모든 권한을 가진다
- **워크스페이스 멤버는 해당 워크스페이스의 WORKSPACE 공개 보드에 자동으로 MEMBER 권한으로 접근 가능하다**
- **워크스페이스 멤버는 해당 워크스페이스의 PUBLIC 보드에 자동으로 VIEWER 권한으로 접근 가능하다**
- **워크스페이스 멤버는 PRIVATE 보드에 접근하려면 별도의 보드별 초대가 필요하다**

### 2. 보드 권한 규칙
- 보드 생성 시 사용자의 워크스페이스 역할이 보드 권한으로 상속된다
- 워크스페이스 ADMIN이 보드를 생성하면 해당 보드의 ADMIN 권한을 가진다
- 워크스페이스 MEMBER가 보드를 생성하면 해당 보드의 ADMIN 권한을 가진다
- 워크스페이스 생성자는 모든 보드에 대해 ADMIN 권한을 가진다
- 보드에는 최소 1명의 ADMIN이 있어야 한다
- 보드 ADMIN은 자신의 역할을 변경할 수 있다
- 워크스페이스 ADMIN은 보드 멤버에게 ADMIN 권한을 부여할 수 있다
- **보드 생성 시 공개 범위를 설정할 수 있다 (기본값: PRIVATE)**
- **보드 생성 후에도 공개 범위를 변경할 수 있다 (ADMIN만 가능)**

### 3. 공개 범위별 접근 권한 규칙
- **PRIVATE 보드**: 
  - 보드에 직접 초대된 멤버만 접근 가능
  - 워크스페이스 멤버라도 별도 초대 없이는 접근 불가
- **WORKSPACE 공개 보드**: 
  - 해당 워크스페이스의 모든 멤버가 자동으로 MEMBER 권한으로 접근 가능
  - 워크스페이스에 초대받은 사용자도 MEMBER 권한으로 접근 가능
- **PUBLIC 보드**: 
  - 링크를 아는 사용자는 누구나 VIEWER 권한으로 접근 가능 (로그인 불필요)
  - 워크스페이스 멤버는 자동으로 VIEWER 권한으로 접근 가능
  - 편집 권한이 필요한 경우 보드별 초대 필요

### 4. 초대 시스템 규칙
- **워크스페이스 초대**: 워크스페이스 ADMIN이 사용자를 워크스페이스에 초대
  - 초대받은 사용자는 해당 워크스페이스의 WORKSPACE 공개 보드에 MEMBER 권한으로 접근 가능
  - 초대받은 사용자는 해당 워크스페이스의 PUBLIC 보드에 VIEWER 권한으로 접근 가능
  - PRIVATE 보드는 별도 보드별 초대 필요
- **보드별 초대**: 보드 ADMIN이 특정 보드에 사용자를 초대
  - 모든 공개 범위의 보드에서 가능 (PRIVATE, WORKSPACE, PUBLIC)
  - 초대 시 보드 권한(ADMIN/MEMBER/VIEWER)을 지정할 수 있다
  - 초대 링크를 생성하여 이메일로 발송하거나 링크를 복사하여 공유할 수 있다
  - 초대받은 사용자가 회원가입을 하지 않았다면 회원가입이 필수이다
  - 초대 만료 기간은 설정 가능하며, 기본값은 7일이다
  - 초대받은 사용자는 해당 보드가 속한 워크스페이스 권한이 없다
  - 이미 보드 멤버인 사용자에게 동일한 권한으로 초대 시 "이미 보드 멤버입니다" 메시지 표시
  - 이미 보드 멤버인 사용자에게 다른 권한으로 초대 시 권한 변경 확인 후 알림 발송

### 5. 공개 범위 변경 규칙
- **PRIVATE → WORKSPACE**: 워크스페이스 멤버들이 자동으로 MEMBER 권한을 받음, 기존 ADMIN은 ADMIN 권한 유지
- **WORKSPACE → PUBLIC**: 기존 멤버들의 권한은 변경되지 않음
- **PUBLIC → PRIVATE**: 외부 사용자는 더 이상 접근 불가, 기존 보드 멤버들의 권한은 유지
- **공개 범위 변경 시**: 모든 기존 멤버에게 알림 발송

### 6. 권한 상속 및 전파
- 워크스페이스에서 멤버가 제거되면 해당 보드에서도 자동으로 제거된다
- 워크스페이스 권한이 보드 권한보다 우선순위가 높다
- **워크스페이스 멤버는 WORKSPACE 공개 보드에 자동으로 MEMBER 권한으로 접근 가능하다**
- **워크스페이스 멤버는 PUBLIC 보드에 자동으로 VIEWER 권한으로 접근 가능하다**

### 7. 데이터 관리 규칙
- 보드 삭제 시 포함된 모든 데이터가 자동으로 삭제된다
- 라벨 삭제 시 할당된 카드가 있으면 경고 메시지를 표시하고 사용자 확인 후 삭제한다
- 라벨 삭제 시 카드는 유지되고 라벨만 제거된다
- 첨부파일 삭제 시 실제 파일도 함께 삭제된다

### 8. 생성자 이전 규칙
- 워크스페이스 생성자만 생성자 권한을 이전할 수 있다
- 생성자 권한은 워크스페이스 멤버 중 ADMIN 역할을 가진 멤버에게만 이전 가능하다
- 워크스페이스 멤버가 1명인 경우 생성자 이전이 불가능하다
- 생성자 이전 시 이중 확인 절차가 필요하다
- 생성자 이전 시 생성자의 비밀번호 재입력이 필요하다
- 생성자 이전 시 모든 멤버에게 알림이 발송된다
- 생성자 이전 이력은 영구적으로 기록된다

### 9. 권한 검증
- 모든 작업 전에 사용자의 권한을 검증한다
- 권한이 없는 작업 시도 시 적절한 오류 메시지를 반환한다

## 권한 검증 구현

### 1. 권한 검증 서비스
```typescript
interface PermissionService {
  // 워크스페이스 권한
  canManageWorkspace(userId: string, workspaceId: string): boolean;
  canInviteMember(userId: string, workspaceId: string): boolean;
  canRemoveMember(userId: string, workspaceId: string): boolean;
  canChangeMemberRole(userId: string, workspaceId: string): boolean;
  
  // 보드 권한
  canManageBoard(userId: string, boardId: string): boolean;
  canEditBoard(userId: string, boardId: string): boolean;
  canViewBoard(userId: string, boardId: string): boolean;
  canInviteBoardMember(userId: string, boardId: string): boolean;
  canRemoveBoardMember(userId: string, boardId: string): boolean;
  canChangeBoardMemberRole(userId: string, boardId: string): boolean;
  canChangeBoardVisibility(userId: string, boardId: string): boolean;
  
  // 공개 보드 접근 권한
  canAccessPublicBoard(boardId: string): boolean;
  canViewPublicBoard(userId: string, boardId: string): boolean;
  
  // 카드 권한
  canManageCard(userId: string, cardId: string): boolean;
  canEditCard(userId: string, cardId: string): boolean;
  canViewCard(userId: string, cardId: string): boolean;
  
  // 댓글 권한
  canManageComment(userId: string, commentId: string): boolean;
  canEditComment(userId: string, commentId: string): boolean;
  
  // 라벨 권한
  canManageLabel(userId: string, boardId: string): boolean;
  canEditLabel(userId: string, boardId: string): boolean;
  
  // 첨부파일 권한
  canUploadAttachment(userId: string, cardId: string): boolean;
  canDeleteAttachment(userId: string, attachmentId: string): boolean;
  canDownloadAttachment(userId: string, attachmentId: string): boolean;
}
```

### 2. 권한 검증 미들웨어
- API 요청 시 자동으로 권한을 검증
- 권한이 없는 경우 403 Forbidden 응답
- 적절한 오류 메시지와 함께 응답

### 3. 프론트엔드 권한 처리
- 권한에 따라 UI 요소 표시/숨김
- 권한이 없는 기능에 대한 안내 메시지
- 권한 상승을 위한 관리자 문의 안내

## 보안 고려사항

### 1. 서버 사이드 검증
- 모든 권한 검증은 서버에서 수행
- 클라이언트 사이드 검증은 UI/UX 목적으로만 사용

### 2. 세션 관리
- 사용자 세션에 권한 정보 포함
- 권한 변경 시 세션 갱신

### 3. 감사 로그
- 권한 관련 작업에 대한 감사 로그 기록
- 권한 변경 이력 추적

## 특별 고려사항

### 1. 라벨 관리
- 라벨 이름 중복은 보드 내에서만 체크한다
- 라벨 색상은 미리 정의된 팔레트에서만 선택 가능하다
- 라벨 삭제 시 할당된 카드가 있으면 경고 메시지를 표시하고 사용자 확인 후 삭제한다

### 2. 보드 공개 범위
- **PRIVATE**: 보드에 직접 초대된 멤버만 접근 가능
- **WORKSPACE**: 해당 워크스페이스의 모든 멤버가 자동으로 MEMBER 권한으로 접근 가능
- **PUBLIC**: 링크를 아는 사용자는 누구나 VIEWER 권한으로 접근 가능 (로그인 불필요)
- 워크스페이스 멤버는 WORKSPACE 공개 보드에 자동으로 MEMBER 권한으로 접근 가능하지만, PRIVATE 보드는 별도 초대 필요

### 3. 초대 시스템
- **워크스페이스 초대**: 워크스페이스 ADMIN이 사용자를 워크스페이스에 초대
  - 초대받은 사용자는 해당 워크스페이스의 WORKSPACE 공개 보드에 MEMBER 권한으로 접근 가능
  - 초대받은 사용자는 해당 워크스페이스의 PUBLIC 보드에 VIEWER 권한으로 접근 가능
  - PRIVATE 보드는 별도 보드별 초대 필요
- **보드별 초대**: 보드 ADMIN이 특정 보드에 사용자를 초대
  - 모든 공개 범위의 보드에서 가능 (PRIVATE, WORKSPACE, PUBLIC)
  - 초대 시 보드 권한(ADMIN/MEMBER/VIEWER)을 지정할 수 있다
  - 초대 링크를 생성하여 이메일로 발송하거나 링크를 복사하여 공유할 수 있다
  - 초대받은 사용자가 회원가입을 하지 않았다면 회원가입이 필수이다
  - 초대 만료 기간은 설정 가능하며, 기본값은 7일이다
  - 초대받은 사용자는 해당 보드가 속한 워크스페이스 권한이 없다
  - 로그인 시 초대 알림과 "보드로 바로 가기" 버튼을 제공한다
  - 메인 대시보드에 "게스트 워크스페이스" 섹션이 존재하여 초대받은 보드 목록을 볼 수 있다

### 4. 개인 워크스페이스 특별 규칙
- 개인 워크스페이스는 다른 멤버가 없음
- 개인 워크스페이스의 보드 공개 범위는 PRIVATE, PUBLIC만 존재
- 개인 워크스페이스의 PUBLIC 보드에 외부 사용자 초대 시 기본 권한은 MEMBER
- 개인 워크스페이스의 PUBLIC 보드에 접근하는 외부 사용자는 기본적으로 VIEWER 권한

### 5. 첨부파일 관리
- 첨부파일 업로드는 카드에 대한 편집 권한이 있는 사용자만 가능
- 첨부파일 삭제는 업로드한 사용자 또는 카드 관리자만 가능
- 첨부파일 다운로드는 보드에 대한 조회 권한이 있는 사용자만 가능
- 첨부파일 크기와 형식은 설정에 따라 제한됨

### 6. 활동 로그
- 모든 중요 활동은 자동으로 로그가 기록됨
- 활동 로그는 감사 및 분석 목적으로 사용됨
- 활동 로그는 설정된 기간 동안 보관됨

## 향후 확장 계획

### 1. 세분화된 권한
- 현재 3단계 권한 체계에서 더 세분화된 권한 체계로 확장 가능
- 예: 카드별 권한, 리스트별 권한 등

### 2. 권한 그룹
- 여러 권한을 묶어서 그룹으로 관리
- 예: "개발자 그룹", "디자이너 그룹" 등

### 3. 조건부 권한
- 특정 조건에 따른 권한 부여
- 예: 프로젝트 진행률에 따른 권한 차등 부여
