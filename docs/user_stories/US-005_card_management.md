# US-005 카드 관리 (F-203, P0)

## 배경
카드는 작업의 최소 단위다. 사용자는 카드를 생성·제목 변경·순서 재정렬(리스트 내)·다른 리스트로 이동·복제·삭제하여 작업을 관리한다. 카드 상세(설명/댓글/라벨/마감일)는 별도 스토리에서 다룬다.

참조: `PRD.md` F-203, `SRS.md` 3.7, `story_map.md` 5번 백본, 데이터 제약 `SRS.md` 5.

## 사용자 스토리
- (생성) 나는 팀원으로서, 할 일을 추가하기 위해 카드를 생성하고 싶다.
- (제목 변경) 나는 사용자로서, 카드 제목을 수정하여 작업 내용을 명확히 하고 싶다.
- (정렬) 나는 사용자로서, 리스트 내 카드의 우선순위를 드래그 앤 드롭으로 재배치하고 싶다.
- (이동) 나는 사용자로서, 진행 단계에 맞게 카드를 다른 리스트로 옮기고 싶다.
- (복제) 나는 사용자로서, 유사한 작업을 빠르게 만들기 위해 카드를 복제하고 싶다.
- (삭제) 나는 사용자로서, 완료되었거나 불필요한 카드를 삭제하고 싶다.

## 수용 기준 (Acceptance Criteria)
1. 생성
   - 카드는 특정 리스트에 종속된다(필수: `listId`).
   - `title`은 필수(1~255자). 성공 시 ID, 초기 `position` 반환.
2. 제목 변경
   - `title` 변경 시 1~255자 유효성 검증.
3. 정렬(드래그 앤 드롭)
   - 리스트 내 카드 순서를 마우스로 변경할 수 있다.
   - 순서 변경 후 관련 카드의 `position`이 일관되게 갱신·저장된다.
4. 이동(리스트 간)
   - 카드를 다른 리스트로 이동할 수 있다.
   - 이동 후 `listId`가 변경되고 목적지 리스트 내 적절한 `position`으로 재배치된다.
5. 복제
   - 기존 카드의 주요 필드를 복제하여 새 카드를 생성한다(식별자/타임스탬프는 새로 발급).
6. 삭제
   - 삭제 성공 시 카드가 목록에서 제거되고, 리스트 내 개수와 `position`이 정합성을 유지한다.
7. 제약
   - 리스트당 카드 수 ≤ 100(`SRS 5`). 초과 생성 시 400 에러.
   - 제목 길이 ≤ 255(`SRS 5`).

## 비기능 (NFR)
- 상호작용 반응 ≤ 0.5초, 페이지 로딩 ≤ 2초
- 보안: JWT 인증, 보드/리스트 접근 권한 검증
- 사용성: DnD 낙관적 업데이트, 이동/복제 후 시 بص각적 피드백 제공

## 테스트 시나리오 (샘플)
- 생성 성공: 유효 title + listId → 201/200 + 리소스 반환
- 생성 실패: 제목 0자/256자 초과 → 400
- 제목 변경 성공/실패(유효성)
- 리스트 내 정렬: DnD 후 `position` 영속화, 새로고침 후 유지
- 리스트 간 이동: `listId` 변경 및 목적지 `position` 정상
- 복제: 새 카드 생성, 원본과 주요 필드 동일(식별자 제외)
- 삭제: 카드 제거, 인접 카드 `position` 연속성 유지

## 범위
- 포함(P0): 카드 생성/조회/수정(제목)/삭제, 리스트 내 정렬, 리스트 간 이동, 복제
- 제외: 카드 상세(설명/댓글/라벨/마감일), 담당자/첨부/체크리스트(별도 스토리)
