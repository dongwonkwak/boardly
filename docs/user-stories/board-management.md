# 보드 관리 유저스토리

## Epic: 보드 관리
**목표**: 사용자가 워크스페이스 내에서 보드를 생성하고 관리할 수 있다.

---

## User Story 1: 보드 생성하기

**As a** 사용자  
**I want to** 새로운 보드를 생성할 수 있다  
**So that** 프로젝트나 작업을 체계적으로 관리할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 워크스페이스 페이지에 있다  
**When** "보드 생성" 버튼을 클릭한다  
**Then** 보드 생성 모달이 표시된다

**Given** 보드 생성 모달이 열려있다  
**When** 보드 제목을 입력한다  
**And** 보드 설명을 입력한다 (선택사항)  
**And** 공개 범위를 선택한다 (PRIVATE/WORKSPACE/PUBLIC)  
**And** "확인" 버튼을 클릭한다  
**Then** 새로운 보드가 생성된다  
**And** 생성된 보드 페이지로 이동한다  
**And** 성공 메시지가 표시된다

#### 비즈니스 규칙
- 보드 제목은 필수 입력 항목이다
- 보드 제목은 1-100자 사이여야 한다
- 보드 설명은 선택사항이며, 최대 500자까지 입력 가능하다
- 공개 범위는 기본값이 PRIVATE이다
- 생성된 보드는 해당 워크스페이스에 속한다
- **PUBLIC 보드로 설정한 경우 고유한 공개 URL이 자동으로 생성된다**
- **개인 워크스페이스의 보드 공개 범위는 PRIVATE, PUBLIC만 존재한다**
- **팀 워크스페이스의 보드 공개 범위는 PRIVATE, WORKSPACE, PUBLIC 모두 사용 가능하다**

#### 예외 상황
**Given** 보드 생성 모달이 열려있다  
**When** 제목 없이 "확인" 버튼을 클릭한다  
**Then** "제목을 입력해주세요" 오류 메시지가 표시된다

**Given** 보드 생성 모달이 열려있다  
**When** 제목을 100자를 초과하여 입력한다  
**And** "확인" 버튼을 클릭한다  
**Then** "제목은 100자 이하여야 합니다" 오류 메시지가 표시된다

#### 테스트 시나리오
1. **정상 생성**: 모든 필수 정보 입력 후 보드 생성
2. **제목 누락**: 제목 없이 생성 시도
3. **제목 길이 초과**: 100자 초과 제목 입력
4. **설명 길이 초과**: 500자 초과 설명 입력
5. **PRIVATE 설정**: PRIVATE로 설정하여 보드 생성
6. **WORKSPACE 설정**: WORKSPACE로 설정하여 보드 생성
7. **PUBLIC 설정**: PUBLIC로 설정하여 보드 생성
8. **공개 URL 생성**: PUBLIC 보드 생성 시 고유 URL 생성 확인
9. **개인 워크스페이스**: 개인 워크스페이스에서 WORKSPACE 옵션 제한 확인
10. **팀 워크스페이스**: 팀 워크스페이스에서 모든 공개 범위 옵션 사용 가능 확인

## User Story 2: 보드 공개 범위 변경하기

**As a** 보드 ADMIN  
**I want to** 보드의 공개 범위를 변경할 수 있다  
**So that** 보드의 접근 권한을 관리할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 보드 설정 페이지에 있다  
**When** "공개 범위" 섹션을 확인한다  
**Then** 현재 공개 범위 상태가 표시된다

**Given** 보드가 PRIVATE 상태이다  
**When** "WORKSPACE로 변경" 버튼을 클릭한다  
**And** 확인 다이얼로그에서 "확인"을 클릭한다  
**Then** 보드가 WORKSPACE로 변경된다  
**And** 워크스페이스 멤버들이 자동으로 MEMBER 권한을 받는다  
**And** "보드가 WORKSPACE로 변경되었습니다" 메시지가 표시된다

**Given** 보드가 WORKSPACE 상태이다  
**When** "PUBLIC로 변경" 버튼을 클릭한다  
**And** 확인 다이얼로그에서 "확인"을 클릭한다  
**Then** 보드가 PUBLIC로 변경된다  
**And** 공개 URL이 생성되고 표시된다  
**And** "보드가 PUBLIC로 변경되었습니다" 메시지가 표시된다

**Given** 보드가 PUBLIC 상태이다  
**When** "PRIVATE로 변경" 버튼을 클릭한다  
**And** 확인 다이얼로그에서 "확인"을 클릭한다  
**Then** 보드가 PRIVATE로 변경된다  
**And** 공개 URL이 비활성화된다  
**And** "보드가 PRIVATE로 변경되었습니다" 메시지가 표시된다

#### 비즈니스 규칙
- 보드 ADMIN만 공개 범위를 변경할 수 있다
- **PRIVATE → WORKSPACE**: 워크스페이스 멤버들이 자동으로 MEMBER 권한을 받음, 기존 ADMIN은 ADMIN 권한 유지
- **WORKSPACE → PUBLIC**: 기존 멤버들의 권한은 변경되지 않음, 공개 URL 자동 생성
- **PUBLIC → PRIVATE**: 외부 사용자는 더 이상 접근 불가, 기존 보드 멤버들의 권한은 유지, 공개 URL 비활성화
- **공개 범위 변경 시**: 모든 기존 멤버에게 알림 발송
- **개인 워크스페이스**: WORKSPACE 옵션은 선택할 수 없다
- **팀 워크스페이스**: 모든 공개 범위 옵션을 선택할 수 있다

#### 예외 상황
**Given** 사용자가 보드 ADMIN이 아니다  
**When** 공개 범위 변경을 시도한다  
**Then** "권한이 없습니다" 오류 메시지가 표시된다

#### 테스트 시나리오
1. **PRIVATE → WORKSPACE**: PRIVATE 보드를 WORKSPACE로 변경
2. **WORKSPACE → PUBLIC**: WORKSPACE 보드를 PUBLIC로 변경
3. **PUBLIC → PRIVATE**: PUBLIC 보드를 PRIVATE로 변경
4. **권한 확인**: ADMIN이 아닌 사용자의 설정 변경 시도
5. **워크스페이스 멤버 권한**: WORKSPACE로 변경 시 워크스페이스 멤버들의 MEMBER 권한 부여 확인
6. **공개 URL 생성**: PUBLIC로 변경 시 고유 URL 생성 확인
7. **공개 URL 비활성화**: PRIVATE로 변경 시 기존 URL 비활성화 확인
8. **알림 발송**: 설정 변경 시 멤버들에게 알림 발송 확인
9. **개인 워크스페이스**: 개인 워크스페이스에서 WORKSPACE 옵션 제한 확인
10. **팀 워크스페이스**: 팀 워크스페이스에서 모든 공개 범위 옵션 사용 가능 확인

## User Story 3: 공개 보드 URL 관리하기

**As a** 보드 ADMIN  
**I want to** PUBLIC 보드의 URL을 관리할 수 있다  
**So that** 외부 사용자와 보드를 공유할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 PUBLIC 보드 설정 페이지에 있다  
**When** "공개 URL" 섹션을 확인한다  
**Then** 현재 공개 URL이 표시된다

**Given** 공개 URL이 표시되어 있다  
**When** "URL 복사" 버튼을 클릭한다  
**Then** 공개 URL이 클립보드에 복사된다  
**And** "URL이 복사되었습니다" 메시지가 표시된다

**Given** 공개 URL이 표시되어 있다  
**When** "URL 새로고침" 버튼을 클릭한다  
**And** 확인 다이얼로그에서 "확인"을 클릭한다  
**Then** 새로운 공개 URL이 생성된다  
**And** 기존 URL은 더 이상 접근할 수 없다  
**And** "새로운 URL이 생성되었습니다" 메시지가 표시된다

#### 비즈니스 규칙
- 보드 ADMIN만 공개 URL을 관리할 수 있다
- PUBLIC 보드만 공개 URL을 가진다
- 공개 URL은 고유해야 한다
- URL 새로고침 시 기존 URL은 즉시 비활성화된다
- URL 새로고침 시 기존에 URL로 접근하던 사용자들에게 영향이 있을 수 있음을 경고한다

#### 예외 상황
**Given** 사용자가 보드 ADMIN이 아니다  
**When** 공개 URL 관리를 시도한다  
**Then** "권한이 없습니다" 오류 메시지가 표시된다

**Given** 보드가 PUBLIC이 아닌 상태이다  
**When** 공개 URL 관리를 시도한다  
**Then** "PUBLIC 보드만 URL을 관리할 수 있습니다" 메시지가 표시된다

#### 테스트 시나리오
1. **URL 복사**: 공개 URL 클립보드 복사
2. **URL 새로고침**: 새로운 공개 URL 생성
3. **권한 확인**: ADMIN이 아닌 사용자의 URL 관리 시도
4. **비PUBLIC 보드**: PRIVATE/WORKSPACE 보드에서 URL 관리 시도
5. **기존 URL 비활성화**: URL 새로고침 시 기존 URL 비활성화 확인

## User Story 4: 워크스페이스 선택하기

**As a** 사용자  
**I want to** 워크스페이스를 선택할 수 있다  
**So that** 원하는 워크스페이스에서 보드를 생성할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 로그인되어 있다  
**When** 메인 페이지에 접속한다  
**Then** 사용자가 속한 워크스페이스 목록이 표시된다

**Given** 워크스페이스 목록이 표시되어 있다  
**When** 특정 워크스페이스를 클릭한다  
**Then** 해당 워크스페이스 페이지로 이동한다  
**And** 해당 워크스페이스의 보드 목록이 표시된다

#### 비즈니스 규칙
- 사용자는 자신이 멤버로 속한 워크스페이스만 볼 수 있다
- 워크스페이스는 개인용과 팀용으로 구분된다
- 개인용 워크스페이스는 사용자당 1개씩 자동 생성된다
- **워크스페이스 멤버는 해당 워크스페이스의 WORKSPACE 공개 보드에 자동으로 MEMBER 권한으로 접근 가능하다**
- **워크스페이스 멤버는 해당 워크스페이스의 PUBLIC 보드에 자동으로 VIEWER 권한으로 접근 가능하다**
- **워크스페이스 멤버라도 PRIVATE 보드에 접근하려면 별도의 보드별 초대가 필요하다**

#### 테스트 시나리오
1. **워크스페이스 목록 조회**: 사용자가 속한 워크스페이스 목록 표시
2. **워크스페이스 선택**: 특정 워크스페이스 클릭 시 해당 페이지로 이동
3. **권한 확인**: 접근 권한이 없는 워크스페이스는 목록에 표시되지 않음
4. **WORKSPACE 공개 보드 접근**: 워크스페이스 멤버의 WORKSPACE 공개 보드 자동 접근 확인
5. **PUBLIC 보드 접근**: 워크스페이스 멤버의 PUBLIC 보드 자동 접근 확인
6. **PRIVATE 보드 접근 제한**: 워크스페이스 멤버의 PRIVATE 보드 접근 제한 확인
