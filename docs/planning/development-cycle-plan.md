# Development Cycle Plan — Boardly

사이클 단위로 개발을 진행하기 위한 운영 방식을 정의합니다. Linear의 Cycle 기능과 연계하여 사용합니다.

---

## 1) 사이클 관리 방식

### 워크플로우 (Linear 상태 흐름)

* **Triage**: 새로 생성된 이슈, 아직 분류 전
* **Backlog**: 우선순위 정리만 된 상태
* **Todo**: 바로 착수할 준비 완료
* **In Progress**: 개발/테스트 진행 중
* **In Review**: PR 리뷰/QA 중
* **Done**: 배포 및 문서 반영 완료
* **Canceled/Duplicate**: 불필요하거나 중복된 이슈

### DoD (Definition of Done)

* 코드 구현 완료
* 단위 테스트/통합 테스트 통과
* PR 머지 및 코드 리뷰 승인
* 문서/캔버스 업데이트 반영
* 배포(또는 배포 가능한 상태) 완료

### 우선순위 지정

* **High**: 이번 사이클 내 반드시 해결해야 하는 핵심 목표
* **Medium**: 가능하다면 이번 사이클 내 처리
* **Low**: 여유 있을 때 진행

### 담당자 지정

* 1인 개발이지만 Linear에서 Assignee를 자기 자신에게 지정해 흐름을 가시화

### 체크인 방식

* 하루 단위로 In Progress 이슈 점검
* PR 발생 시 In Review로 이동
* 사이클 종료 전 목표 달성 여부 리뷰

---

## 2) 사이클 목표 (Cycle Goals)

사이클 목표는 사이클 시작 시 별도로 정의합니다. 예시:

* **사이클 1 목표**: 회원가입 + 로그인 + 워크스페이스 생성 기능 완료

---

## 3) 자동화 규칙 (Workflow Automation)

* Project X 내 생성되는 새 이슈 → 현재 진행 중인 Cycle에 자동 배정
* PR 생성 시 상태를 In Review로 자동 전환

---

## 4) 사이클 종료 후 회고 (Retro)

* 달성된 목표 vs 미달성 목표 검토
* 미달성 이슈는 다음 사이클로 이동
* 개선할 프로세스 피드백 반영
