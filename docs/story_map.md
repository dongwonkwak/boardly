# Boardly Story Map

문서 목적: PRD와 SRS를 바탕으로 사용자 여정(Backbone)과 하위 사용자 작업을 구조화하여 MVP(P0)와 차기 릴리즈(P1) 별 우선순위와 범위를 한눈에 파악할 수 있도록 한다.

참조: [PRD](PRD.md), [SRS](SRS.md)

## 사용자 페르소나 요약
| 페르소나 | 역할/맥락 | 핵심 니즈 |
|---|---|---|
| 박준서 (PM) | 소규모 개발팀 스프린트 운영 | 팀 현황 실시간 파악, 시각적 스프린트 관리 |
| 김지아 (마케터) | 다수 프로젝트 동시 운영 | 프로젝트 분리 관리, 마감 관리 |
| 이하은 (학생 조장) | 팀플 관리 | 역할 분담·자료 취합, 무료 협업툴 |

## Backbone (사용자 여정의 상위 활동)
1) 온보딩·계정 관리 → 2) 워크스페이스 구성 → 3) 보드 생성·설정 → 4) 리스트로 워크플로 설계 → 5) 카드로 작업 관리 → 6) 카드 상세로 협업·맥락 공유 → 7) 정리·우선순위화(드래그 앤 드롭/즐겨찾기) → 8) 진행 추적(활동 내역/알림) → 9) 다국어 환경 → 10) 접근제어(RBAC)·초대 → 11) 데이터 관리(삭제 정책/백업)

각 활동별 스토리(Tasks)와 우선순위(P0/P1)는 아래 섹션을 따른다.

---

## 1. 온보딩·계정 관리 (F-101)
- 목표: 사용자가 안전하게 가입/로그인하고 개인 설정(언어 포함)을 관리한다.
- 사용자 스토리
  - [P0] 이메일/비밀번호로 회원가입/로그인/로그아웃 (JWT) — PRD F-101, SRS 3.1
  - [P0] 프로필 조회/수정, 비밀번호 변경(규칙 검증) — SRS 3.1
  - [P0] UI 언어 설정 변경 — SRS 6.5

## 2. 워크스페이스 구성 (F-150)
- 목표: 개인/팀 단위로 보드를 그룹화하고 맥락을 분리한다.
- 사용자 스토리
  - [P0] 워크스페이스 생성/조회/수정/삭제, 타입(Personal/Team) — PRD F-150, SRS 3.2
  - [P1] 멤버 관리(초대·역할) — 협업 기능 연계 — SRS 3.4, 3.3

## 3. 보드 생성·설정 (F-201)
- 목표: 프로젝트 단위 작업 공간 생성 및 관리.
- 사용자 스토리
  - [P0] 보드 생성/조회/수정/삭제/복제 — PRD F-201, SRS 3.5
  - [P0] 즐겨찾기 관리 — SRS 3.5
  - [P1] 보드 협업 초대/역할 — PRD F-402, SRS 3.4, 3.3

## 4. 리스트로 워크플로 설계 (F-202)
- 목표: 단계별 진행 흐름(예: To Do → Doing → Done)을 정의한다.
- 사용자 스토리
  - [P0] 리스트 생성/이름·색상 변경/순서 변경(드래그 앤 드롭)/삭제 — PRD F-202, SRS 3.6

## 5. 카드로 작업 관리 (F-203)
- 목표: 작업 단위를 생성·이동·정렬하며 진행을 관리한다.
- 사용자 스토리
  - [P0] 카드 생성/제목 변경/이동(리스트 간 포함)/순서 변경/복제 — PRD F-203, SRS 3.7

## 6. 카드 상세로 협업·맥락 공유 (F-301)
- 목표: 업무 맥락을 상세히 기록하고 협업한다.
- 사용자 스토리
  - [P0] 설명(마크다운) — PRD F-301, SRS 3.7
  - [P0] 댓글 — PRD F-301, SRS 3.7
  - [P0] 라벨 — PRD F-301, SRS 3.7
  - [P0] 마감일(완료 처리 포함) — PRD F-301, SRS 3.7
  - [P1] 담당자 할당 — PRD F-301(세부), SRS 3.7(협업 연계)
  - [P1] 첨부파일 — PRD F-703, SRS 3.7
  - [P1] 체크리스트 — PRD F-702

## 7. 정리·우선순위화 (드래그 앤 드롭) (F-401)
- 목표: 변화에 맞춰 손쉽게 재정렬·재배치한다.
- 사용자 스토리
  - [P0] 카드/리스트 드래그 앤 드롭 — PRD F-401, SRS 3.6/3.7

## 8. 진행 추적 (활동 내역/알림) (F-601, F-501)
- 목표: 누가 언제 무엇을 했는지 투명하게 추적하고 중요한 변화를 놓치지 않는다.
- 사용자 스토리
  - [P0] 보드 활동 내역(타임라인) — PRD F-601, SRS 3.8
  - [P1] 인앱 알림 및 개인 알림 센터 — PRD F-501/F-603, SRS 3.4.4, 3.9
  - [P1] 워크스페이스 활동 통합 — PRD F-602
  - [P1] 고급 알림 채널(이메일/푸시) — SRS 7. P1 기능

## 9. 다국어 환경 (F-701)
- 목표: 한국어/영어 지원 및 동적 전환.
- 사용자 스토리
  - [P0] 한국어/영어 UI, 브라우저 언어 감지·수동 변경 — PRD F-701, SRS 6.5
  - [P1+] 추가 언어 지원(일/중 등) — SRS 7. P1 기능

## 10. 접근제어(RBAC)·초대 (협업)
- 목표: 역할 기반 접근제어와 초대로 안전한 협업.
- 사용자 스토리
  - [P1] 워크스페이스 역할(OWNER/ADMIN/MEMBER)과 권한 매트릭스 — SRS 3.3, workspace-board-permissions.md
  - [P1] 보드 역할(BOARD_ADMIN/BOARD_EDITOR/BOARD_VIEWER)과 권한 매트릭스 — SRS 3.3, workspace-board-permissions.md
  - [P1] 권한 우선순위 규칙(워크스페이스 권한 > 보드 권한) — workspace-board-permissions.md
  - [P1] 워크스페이스/보드 멤버 초대·역할 관리 — SRS 3.4, workspace-board-permissions.md
  - [P1] 초대 상태 관리(PENDING/ACCEPTED/DECLINED/EXPIRED) — workspace-board-permissions.md
  - [P1] 초대 만료 관리(7일 자동 만료) — workspace-board-permissions.md

## 11. 데이터 관리 (삭제 정책/백업)
- 목표: 안전한 소프트 삭제와 복구, 백업 제공.
- 사용자 스토리
  - [P0] 보드 휴지통(소프트 삭제, 30일 보관) — SRS 3.10.2
  - [P0] 워크스페이스 삭제 가드(사전 조건/확인 절차) — SRS 3.10.1
  - [P1] 데이터 백업/복구 — SRS 3.10.3, 5.1(추가 엔티티)
  - [P1] 데이터 내보내기(CSV/JSON 등) — SRS 7. P1 기능
  - [P1+] 관리자 삭제 정책(승인 워크플로, 정책 커스터마이징) — SRS 7. P1 기능
  - [P1+] 데이터 복구 서비스(영구 삭제 후 백업 기반 복구) — SRS 7. P1 기능

## 12. 공개 API(써드파티 연동)
- 목표: 외부 애플리케이션이 보드/카드 데이터를 안전하게 읽고 쓰도록 한다.
- 사용자 스토리
  - [P1+] 공개 API 제공(OpenAPI 명세, 키 발급/권한 범위) — SRS 7. P1 기능

## 릴리즈 슬라이스(Release Slices)

### R1: MVP (P0)
- 계정: 가입/로그인/로그아웃, 프로필/비번 변경, 언어 설정
- 워크스페이스: CRUD, 타입 구분 (Personal/Team)
- 보드: CRUD, 복제, 즐겨찾기
- 리스트: CRUD, 색상, 순서(드래그 앤 드롭)
- 카드: CRUD, 이동/정렬(드래그 앤 드롭), 복제
- 카드 상세: 설명, 댓글, 라벨, 마감일
- 활동 내역: 보드 단위 타임라인
- 다국어: 한국어/영어 지원, 동적 전환
- 삭제 정책: 워크스페이스/보드 기본 정책(소프트 삭제 포함)

### R2: 협업·알림(Next, P1)
- 초대·역할: 워크스페이스/보드 멤버 초대, RBAC, 권한 매트릭스, 권한 우선순위 규칙
- 초대 관리: 초대 상태 추적, 7일 만료 관리, 이메일/링크 초대
- 카드 상세 확장: 담당자, 첨부파일, 체크리스트
- 알림: 인앱 알림/개인 알림 센터, 워크스페이스 활동 통합, 고급 알림 채널(이메일/푸시)
- 실시간 동기화(WebSocket): 보드 변경 실시간 반영, 협업 상태 표시
- 데이터 관리 확장: 백업 제공, 데이터 내보내기(CSV/JSON), 관리자 삭제 정책(승인 워크플로)
- 검색/필터, 카드 템플릿, 통계 대시보드(검토)
- 다국어 확장: 추가 언어(일/중 등)
- 공개 API: 써드파티 연동(OpenAPI)

## 수용 기준(샘플) — 핵심 흐름
- 가입/로그인
  - 비밀번호 규칙 충족 시에만 가입 가능(최소 8자, 대/소문자/특수문자 포함)
  - 성공 시 JWT 발급 및 보호 리소스 접근 가능
- 카드 이동
  - 같은 리스트 내 순서 변경 및 다른 리스트로 이동 시, 즉시 UI 반영 및 저장
- 활동 내역
  - 카드 생성/이동/수정/댓글 추가 이벤트가 시간순으로 기록·조회됨
- 다국어
  - 브라우저 언어 감지 기본값, 사용자가 즉시 전환 시 전체 UI 텍스트 변경
- 권한 검증
  - 워크스페이스 권한이 보드 권한보다 우선 적용
  - OWNER/ADMIN은 모든 보드에 모든 권한
  - 멤버십 및 역할 변경 시 즉시 권한 적용
- 초대 시스템
  - 이메일/링크 초대, 7일 만료, 상태 추적(PENDING/ACCEPTED/DECLINED/EXPIRED)
  - 워크스페이스 초대 시 MEMBER 역할, 보드 초대 시 BOARD_VIEWER 역할 기본 부여

## 데이터 제약(적용 범위)
- 워크스페이스(≤10)/보드(≤50)/리스트(≤20)/리스트당 카드(≤100)
- 카드 제목 ≤255자, 설명 ≤10,000자, 첨부파일 ≤10MB (P1)

## 비기능 요구 요약(DoD 체크)
- 페이지 로딩 ≤2초, 상호작용 반응 ≤0.5초
- XSS/CSRF/SQLi 대응, BCrypt, JWT, Rate Limiting
- 반응형 UI, 드래그 앤 드롭, Lighthouse ≥85
- 멀티테넌시: 워크스페이스 간 완전한 데이터 격리
- 권한 관리: RBAC, 권한 우선순위, 감사 로그
