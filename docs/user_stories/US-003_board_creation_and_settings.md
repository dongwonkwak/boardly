# US-003 보드 생성·설정 (F-201, P0)

## 배경
보드는 프로젝트 단위의 작업 공간이다. 사용자는 워크스페이스 내에서 보드를 생성하고, 이름/설명 수정, 즐겨찾기, 복제 및 삭제를 수행한다.

참조: `PRD.md` F-201, `SRS.md` 3.5, 활동/삭제 정책 `SRS.md` 3.10.2, 데이터 제약 `SRS.md` 5.

## 사용자 스토리
- (생성) 나는 PM으로서, 새로운 프로젝트를 시작할 때 워크스페이스 내 보드를 생성하고 싶다.
- (수정) 나는 사용자로서, 보드의 이름/설명 등을 수정하고 싶다.
- (즐겨찾기) 나는 사용자로서, 자주 쓰는 보드를 즐겨찾기에 추가/해제하고 싶다.
- (복제) 나는 사용자로서, 유사한 구조의 새 프로젝트를 빠르게 시작하기 위해 기존 보드를 복제하고 싶다.
- (삭제) 나는 권한이 있는 사용자로서, 보드를 안전하게 삭제(휴지통 이동)하고 필요 시 복구하고 싶다.

## 수용 기준 (Acceptance Criteria)
1. 생성
   - 보드는 특정 워크스페이스에 종속된다(필수: `workspaceId`).
   - `name`은 필수(1~100자). 성공 시 ID, 생성 시각 반환.
2. 조회/목록
   - 사용자는 접근 권한이 있는 보드만 조회 가능.
   - 목록은 즐겨찾기 우선 정렬 옵션을 지원한다(선택).
3. 수정
   - 이름/설명 수정 가능. 유효성 검증 실패 시 필드별 에러 메시지.
4. 즐겨찾기
   - 토글 방식으로 on/off 가능. 사용자별 즐겨찾기 상태 저장.
5. 복제
   - 기존 보드와 동일한 구조를 가진 새 보드를 생성한다(메타/리스트 구조 중심; 세부 범위는 구현 시점 명세에 따름).
6. 삭제(휴지통)
   - 권한: 워크스페이스 소유자 또는 해당 보드 소유자만 가능(`SRS 3.10.2`).
   - 소프트 삭제: 삭제 즉시 휴지통 상태로 전환, 멤버 접근 차단.
   - 보관 기간: 30일 후 자동 영구 삭제. 보관 기간 중 복구 가능(권한 동일).
7. 제약
   - 워크스페이스당 보드 수 ≤ 50(`SRS 5. 데이터 제약`). 초과 시 400 에러.

## 비기능 (NFR)
- 성능: 보드 생성/복제 ≤ 800ms, 목록 조회 ≤ 500ms
- 보안: JWT 인증, 보드 접근 권한 검증
- 사용성: 즐겨찾기 즉시 반영(낙관적 업데이트), 삭제 전 경고/확인 절차 제공

## 테스트 시나리오 (샘플)
- 생성 성공: 유효 name + workspaceId 존재 → 201/200
- 생성 실패: workspaceId 미존재/권한 없음 → 404/403
- 즐겨찾기 토글 → 상태 on/off 저장 및 목록 정렬 반영
- 복제 성공 → 새 보드 생성, 원본과 구조 동일 검증
- 삭제 → 휴지통 상태 전환, 접근 불가 확인, 30일 후 영구 삭제 스케줄링
- 복구 → 휴지통 보드 복구 성공, 활동 로그 기록 확인(선택)

## 범위
- 포함(P0): 보드 생성/조회/수정/삭제(휴지통), 복제, 즐겨찾기
- 제외(P1): 보드 멤버 초대/역할, 고급 설정, 실시간 협업 상태

## 오류 응답(표준)
- 참고: `../errors.md`
- 상태 코드 적용
  - 403 PermissionDenied: 보드 접근/변경 권한 없음
  - 404 NotFound: `workspaceId` 또는 보드 미발견
  - 409 ResourceConflict: 즐겨찾기/수정 중 충돌, 보드명 중복(정책 시)
  - 412 PreconditionFailed: 온보딩/사전 조건 미충족 시 보드 생성 차단
  - 422 BusinessRuleViolation: 워크스페이스 당 보드 50개 초과
  - 500 InternalError
- 응답 포맷: `code`, `message`, `timestamp`, `path`, `context`
