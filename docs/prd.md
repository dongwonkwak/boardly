# Boardly 제품 요구사항 정의서 (PRD)

## 1. 개요 (Overview)

Boardly는 팀과 개인이 작업을 시각적으로 구성하고, 진행 상황을 추적하며, 원활하게 협업할 수 있도록 돕는 직관적인 칸반 보드 기반의 프로젝트 관리 도구입니다. 사용자는 워크스페이스 내에서 보드, 리스트, 카드를 활용하여 복잡한 프로젝트의 워크플로우를 한눈에 파악하고 생산성을 극대화할 수 있습니다.


## 2. 문제 정의 및 목표 (Problem & Objectives)

### 2.1. 문제점 (The Problem)

많은 팀과 개인이 프로젝트를 진행하며 다음과 같은 어려움을 겪습니다.

- **분산된 정보**: 이메일, 메신저, 문서 등 여러 채널에 업무 정보가 흩어져 있어 진행 상황 파악이 어렵습니다.
- **업무 투명성 부족**: 누가 어떤 일을 하고 있는지, 각 업무의 마감일은 언제인지 명확하게 공유되지 않아 병목 현상이 발생합니다.
- **비효율적인 소통**: 업무 상태를 확인하기 위한 불필요한 미팅과 메시지가 반복되어 생산성이 저하됩니다.

### 2.2. 해결 방안 (The Solution)

Boardly는 중앙화된 시각적 워크스페이스를 제공하여 이 문제들을 해결합니다.

- **시각적 워크플로우**: 'To Do', 'In Progress', 'Done'과 같은 단계별 리스트를 통해 프로젝트의 흐름을 직관적으로 보여줍니다.
- **정보의 중앙화**: 모든 업무(카드)에 관련된 정보(설명, 파일, 댓글, 마감일)를 한곳에 모아 관리합니다.
- **실시간 협업**: 팀원들의 활동이 실시간으로 보드에 반영되어 투명한 소통과 빠른 의사결정을 돕습니다.

### 2.3. 프로젝트 목표 (Project Goals)

이 프로젝트는 가상의 서비스 'Boardly'를 기획부터 배포까지 직접 구현해보는 개인 포트폴리오 프로젝트입니다. 목표는 다음과 같습니다.

- **프로덕트 기획 및 관리 능력 입증**: 사용자 문제 정의, 기능 요구사항 구체화(PRD) 등 전체 프로덕트 관리 사이클에 대한 이해도를 보여줍니다.
- **핵심 기능의 성공적인 구현 및 배포**: MVP(최소 기능 제품)로 정의된 P0 기능 전체를 안정적으로 구현하고 사용 가능한 상태로 배포합니다.
- **기술 스택 활용 능력 증명**: React, PostgreSQL 등 특정 기술 스택을 활용하여 실시간 동기화, 사용자 인증 등 복잡한 기능을 구현하는 능력을 보여줍니다.

#### 성공 지표 (Success Metrics)

- **기능 완성도**: 기획된 P0 기능들이 버그 없이 모두 정상적으로 동작하는가?
- **코드 퀄리티**: 재사용성과 유지보수성을 고려하여 컴포넌트를 설계했는가?
- **사용자 경험(UX)**: 타겟 사용자의 'Pain Points'를 해결하는 직관적이고 편리한 UI/UX를 제공하는가? (Lighthouse 성능 점수 85점 이상 달성)

## 4. 핵심 기능 요구사항 (Features & Requirements)

### P0 (필수 핵심 기능 - MVP)

| 기능 ID | 기능명 | 설명 | 사용자 스토리 (User Story) |
|---------|--------|------|---------------------------|
| **F-101** | 사용자 계정 관리 | 사용자는 이메일/비밀번호로 회원가입, 로그인/로그아웃을 할 수 있으며, 로그인 후 자신의 프로필 정보와 비밀번호를 관리할 수 있다. | 가입한 사용자로서, 내 계정 정보를 최신으로 유지하고 보안을 위해 비밀번호를 변경하고 싶다. |
| **F-150** | 워크스페이스 관리 | 모든 보드를 그룹화하는 최상위 공간. **개인용(Personal)과 팀용(Team)**으로 구분된다. 사용자는 여러 워크스페이스를 생성하고 참여할 수 있다. | 사용자로서, 개인 프로젝트와 팀 프로젝트를 분리하여 관리하기 위해 별도의 워크스페이스를 만들고 싶다. |
| **F-201** | 보드 (Board) | 워크스페이스 내에 생성되는 프로젝트 단위의 작업 공간. 생성, 이름 변경, 삭제, 즐겨찾기, 복제 기능을 제공한다. | PM으로서, 새로운 프로젝트를 시작할 때 해당 프로젝트를 위한 보드를 생성하고 싶다. |
| **F-202** | 리스트 (List) | 보드 내의 작업 단계 (예: To Do, Doing, Done). 생성, 이름 변경, 색상 변경, 순서 변경(Drag & Drop), 삭제 기능을 제공한다. | 사용자로서, 내 업무 흐름에 맞게 '아이디어', '디자인 중', '개발 중', '완료' 같은 리스트를 만들고 싶다. |
| **F-203** | 카드 (Card) | 개별 업무 단위. 리스트 내에서 생성, 제목 변경, 마크다운 설명 작성, 순서 변경, 다른 리스트로 이동(Drag & Drop), 복제가 가능하다. | 팀원으로서, 내가 맡은 업무를 'To Do' 리스트에 카드로 생성하고 싶다. |
| **F-301** | 카드 상세 기능 | 카드를 클릭하면 상세 내용을 보고 편집할 수 있다. 설명, 댓글, 담당자 할당, 라벨, 마감일 기능을 포함한다. | 사용자로서, 카드를 클릭하여 업무에 대한 상세 정보(설명, 마감일, 담당자)를 확인하고 싶다. |
| **F-401** | 드래그 앤 드롭 | 카드와 리스트의 순서를 드래그 앤 드롭으로 변경할 수 있다. 카드는 같은 리스트 내에서의 순서 변경과 다른 리스트로의 이동이 모두 가능하다. | 사용자로서, 업무 상황 변화에 따라 카드를 쉽게 다른 단계로 옮기고 싶다. |
| **F-601** | 활동 내역 (Activity Feed) | 보드 내에서 발생한 모든 활동을 시간순으로 기록하고 표시한다. 카드 생성/이동/수정, 댓글 추가, 담당자 할당 등의 활동이 포함되며 다국어 지원한다. | 사용자로서, 보드에서 누가 언제 무엇을 했는지 추적하여 업무 진행 상황을 파악하고 싶다. |
| **F-701** | 다국어 지원 | 영어와 한국어를 지원한다. 사용자의 브라우저 언어를 감지하거나 수동으로 언어를 변경할 수 있다. | 한국어 사용자로서, 한국어 인터페이스로 서비스를 이용하고 싶다. |

#### 카드 상세 기능 세부사항

| 기능 | 설명 | 사용자 스토리 (User Story) |
|------|------|-------------|
| **설명 (Description)** | 카드에 대한 상세 설명을 마크다운 형식으로 작성할 수 있다. | 사용자로서, 업무에 대한 자세한 내용을 마크다운으로 기록하고 싶다. |
| **댓글 (Comments)** | 카드에 대해 팀원들과 의견을 나눌 수 있다. 댓글 작성, 수정, 삭제가 가능하다. | 팀원들로서, 특정 업무에 대해 의견을 교환하고 싶다. |
| **담당자 할당 (Assignees)** | 보드에 참여한 멤버를 카드 담당자로 지정할 수 있다. 복수 담당자 지정 가능하다. (MVP에서는 개인 사용자 중심, P1에서 협업 기능 확장) | PM으로서, 각 업무의 책임자를 명확히 지정하고 싶다. |
| **라벨 (Labels)** | '버그', '긴급', '디자인' 등 색상과 이름으로 카드를 분류할 수 있다. | 사용자로서, 업무의 성격이나 우선순위를 시각적으로 구분하고 싶다. |
| **마감일 (Due Date)** | 카드의 마감 날짜와 시간을 설정하고 완료 처리할 수 있다. | 사용자로서, 업무의 마감일을 설정하고 기한을 놓치지 않도록 관리하고 싶다. |

## 7. 비기능적 요구사항 (Non-Functional Requirements)

- **성능 (Performance)**: 페이지 로딩 시간은 2초 이내, 카드 이동 및 실시간 동기화는 0.5초 이내에 반응해야 한다.
- **사용성 (Usability)**: 별도의 튜토리얼 없이도 사용자가 핵심 기능을 쉽게 탐색하고 사용할 수 있어야 한다.
- **보안 (Security)**: 모든 사용자 데이터는 암호화되어야 하며, 기본적인 보안 취약점(XSS, CSRF)에 대응해야 한다.
- **확장성 (Scalability)**: 최소 10만 명의 사용자와 수백만 개의 카드를 처리할 수 있도록 시스템을 설계해야 한다.
