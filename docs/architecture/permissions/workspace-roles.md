# 워크스페이스 및 보드 권한 시스템 정의

## 개요

이 문서는 Boardly에서 워크스페이스와 보드의 권한 시스템을 정의합니다. 멀티테넌시 아키텍처를 기반으로 한 격리된 협업 공간에서 사용자가 가질 수 있는 역할과 권한을 명확히 합니다.

## 🏢 워크스페이스: 우리 팀의 독립된 디지털 오피스

워크스페이스는 협업이 일어나는 가장 큰 단위의 컨테이너입니다. 특정 팀이나 회사, 프로젝트 그룹을 위한 하나의 독립된 디지털 공간이라고 생각하면 쉽습니다.

**역할**: 팀원(멤버)과 모든 데이터(보드, 카드 등)를 담는 그릇입니다.

**핵심 특징**: 
- 각 워크스페이스는 다른 워크스페이스로부터 완벽히 격리됩니다
- A 워크스페이스의 멤버는 B 워크스페이스의 존재 자체를 알 수 없습니다
- 이는 멀티테넌시 아키텍처를 통해 구현되며, 데이터 보안의 핵심입니다

**멤버십**: 워크스페이스에 소속된 사용자를 **'정식 멤버(Full Member)'**라고 부릅니다. 이들은 해당 공간의 일원으로서 기본적인 활동 권한을 가집니다.

## 📝 보드: 아이디어를 구체화하는 작업 공간

보드는 워크스페이스라는 큰 사무실 안에 있는 개별 프로젝트 룸 또는 화이트보드입니다. 실제 업무와 관련된 아이디어를 시각화하고 구체적인 작업을 관리하는 공간입니다.

**역할**: 리스트와 카드를 통해 특정 프로젝트나 업무 흐름을 관리합니다.

**핵심 특징**: 보드는 접근 권한을 설정할 수 있는 중요한 속성을 가집니다.

### 보드 유형

#### 공개 보드 (Public to Workspace)
- 워크스페이스의 '공용 라운지'와 같습니다
- 해당 워크스페이스의 정식 멤버라면 누구나 별도의 초대 없이 접근할 수 있습니다
- 기본적으로 모든 멤버가 읽기/쓰기 권한을 가집니다

#### 비공개 보드 (Private)
- '잠겨있는 회의실'과 같습니다
- 오직 명시적으로 초대받은 사용자만이 접근할 수 있습니다
- 다른 멤버들에게는 보이지 않습니다
- 외부 협력사와의 협업에 주로 사용됩니다

## 💌 초대 시스템: 정직원과 방문객의 차이

사용자를 협업 공간으로 부르는 방식은 두 가지로 나뉘며, 이는 권한 부여의 핵심적인 차이를 만듭니다.

### 워크스페이스 단위 초대

**결과**: 정식 멤버가 됩니다.

**비유**: 회사에 정직원으로 채용되어 사원증을 받는 것과 같습니다.

**권한**: 
- 워크스페이스 내 모든 '공개 보드'에 대한 접근 권한을 자동으로 얻습니다
- 워크스페이스 설정에 따라 기본 역할(보통 MEMBER)이 부여됩니다
- 워크스페이스 내에서 보드를 생성할 수 있습니다

### 보드 단위 초대

**결과**: 특정 보드에만 접근 가능한 게스트가 됩니다.

**비유**: 특정 회의에만 참석하기 위해 방문증을 받는 것과 같습니다.

**권한**: 
- 초대받은 '비공개 보드' 하나에만 접근할 수 있습니다
- 다른 공간은 전혀 볼 수 없습니다
- 주로 외부 협력사와의 협업에 사용됩니다
- 워크스페이스 멤버가 아닌 외부 사용자도 초대 가능합니다

## 👑 권한 계층: 직책과 실무 역할의 분리

워크스페이스와 보드는 각각 독립적인 역할(Role) 시스템을 가집니다.

### 워크스페이스 역할 (회사 직책)

워크스페이스 전체에 영향을 미치는 관리 권한입니다.

#### OWNER (소유자)
**설명**: 워크스페이스의 최고 권한자로, 워크스페이스의 모든 측면을 관리할 수 있습니다.

**권한**:
- ✅ 워크스페이스 설정 변경
- ✅ 워크스페이스 삭제
- ✅ 멤버 초대 및 제거
- ✅ 모든 멤버의 역할 변경
- ✅ 모든 보드 생성, 수정, 삭제
- ✅ 모든 보드의 모든 권한
- ✅ 워크스페이스 통계 및 분석 접근
- ✅ 워크스페이스 백업 및 복원

**제한사항**:
- ❌ OWNER 역할을 다른 사용자에게 이전할 수 없음 (워크스페이스 삭제 후 재생성 필요)

#### ADMIN (관리자)
**설명**: 워크스페이스의 일상적인 관리를 담당하며, OWNER 다음으로 높은 권한을 가집니다.

**권한**:
- ✅ 멤버 초대 및 제거
- ✅ MEMBER, GUEST 역할 변경
- ✅ 모든 보드 생성, 수정, 삭제
- ✅ 모든 보드의 모든 권한
- ✅ 워크스페이스 설정 일부 변경
- ✅ 워크스페이스 통계 및 분석 접근
- ✅ 워크스페이스 백업

**제한사항**:
- ❌ OWNER 역할 변경 불가
- ❌ ADMIN 역할을 다른 사용자에게 부여 불가
- ❌ 워크스페이스 삭제 불가

#### MEMBER (멤버)
**설명**: 워크스페이스의 일반 구성원으로, 대부분의 협업 기능을 사용할 수 있습니다.

**권한**:
- ✅ 보드 생성, 수정, 삭제 (자신이 생성한 보드)
- ✅ 보드에 카드 추가, 수정, 삭제
- ✅ 보드에 댓글 작성
- ✅ 보드 활동 피드 확인
- ✅ 워크스페이스 멤버 목록 확인
- ✅ 워크스페이스 설정 확인 (읽기 전용)
- ✅ 워크스페이스 통계 확인 (읽기 전용)

**제한사항**:
- ❌ 다른 사용자 초대 불가
- ❌ 다른 사용자의 역할 변경 불가
- ❌ 다른 사용자가 생성한 보드 삭제 불가
- ❌ 워크스페이스 설정 변경 불가

### 보드 역할 (프로젝트 실무 역할)

특정 보드 내에서만 적용되는 세부 권한입니다.

#### BOARD_ADMIN (보드 관리자)
**설명**: 보드 설정을 변경하고 멤버를 추가/삭제할 수 있습니다.

**권한**:
- ✅ 보드 설정 변경 (제목, 설명, 공개/비공개 설정)
- ✅ 보드 멤버 초대 및 제거
- ✅ 보드 내 모든 카드 관리
- ✅ 보드 삭제
- ✅ 보드 템플릿 생성 및 적용

#### BOARD_EDITOR (보드 편집자)
**설명**: 카드를 생성하고 수정하는 등 콘텐츠 작업을 합니다.

**권한**:
- ✅ 카드 생성, 수정, 삭제
- ✅ 리스트 생성, 수정, 삭제
- ✅ 댓글 작성
- ✅ 첨부파일 업로드
- ✅ 체크리스트 관리
- ✅ 라벨 관리

#### BOARD_VIEWER (보드 뷰어)
**설명**: 모든 내용을 읽을 수만 있습니다.

**권한**:
- ✅ 보드 내용 조회
- ✅ 카드 내용 확인
- ✅ 댓글 읽기
- ✅ 활동 피드 확인

**제한사항**:
- ❌ 카드 생성/수정 불가
- ❌ 댓글 작성 불가
- ❌ 보드 설정 변경 불가

## 초대 및 멤버십 관리

### 초대 프로세스

#### 워크스페이스 초대
1. OWNER/ADMIN이 이메일로 사용자 초대
2. 초대된 사용자가 이메일 링크를 통해 가입/로그인
3. 워크스페이스에 정식 멤버로 추가
4. 기본 역할(MEMBER) 부여
5. 모든 공개 보드에 자동 접근 권한 획득

#### 보드 초대
1. 보드 소유자/관리자가 이메일로 사용자 초대
2. 초대된 사용자가 이메일 링크를 통해 접근
3. 해당 보드에만 접근 가능한 게스트로 추가
4. 보드 역할(BOARD_VIEWER/EDITOR) 부여
5. 워크스페이스 멤버가 아닌 경우에도 초대 가능

### 멤버십 종료

#### 워크스페이스 멤버십 종료
- OWNER/ADMIN이 멤버를 제거
- 제거된 멤버가 생성한 보드는 워크스페이스에 남음
- 제거된 멤버는 모든 워크스페이스 보드에 접근 불가

#### 보드 멤버십 종료
- 보드 관리자가 멤버를 제거
- 제거된 멤버는 해당 보드에만 접근 불가
- 워크스페이스 멤버십에는 영향 없음

## 보안 고려사항

### 1. 데이터 격리
- 워크스페이스 간 완전한 데이터 격리
- 멀티테넌시 아키텍처로 구현
- 각 워크스페이스는 독립적인 데이터베이스 스키마 사용

### 2. 권한 상속
- 상위 역할은 하위 역할의 모든 권한을 상속받음
- 역할 변경 시 즉시 권한이 적용됨

### 3. 감사 로그
- 모든 권한 변경 사항은 감사 로그에 기록
- 역할 변경, 멤버 추가/제거, 보드 생성/삭제 등 추적

### 4. 세션 관리
- 역할 변경 시 활성 세션에 즉시 반영
- 권한이 없는 기능 접근 시 403 Forbidden 응답

## API 응답 예시

### 워크스페이스 멤버 정보 조회
```json
{
  "workspace_id": "ws_123",
  "user_id": "user_456",
  "role": "ADMIN",
  "membership_type": "FULL_MEMBER",
  "permissions": {
    "invite_members": true,
    "remove_members": true,
    "change_roles": true,
    "create_boards": true,
    "delete_boards": true,
    "manage_workspace": true
  },
  "joined_at": "2025-01-27T10:00:00Z"
}
```

### 보드 멤버 정보 조회
```json
{
  "board_id": "board_789",
  "user_id": "user_456",
  "role": "BOARD_EDITOR",
  "membership_type": "GUEST",
  "permissions": {
    "create_cards": true,
    "edit_cards": true,

    "create_lists": true,
    "add_comments": true,
    "upload_attachments": true

```

### 권한 오류 응답
```json
{
  "error": "WS-INSUFFICIENT_PERMISSION",
  "message": "이 작업을 수행할 권한이 없습니다.",
  "required_role": "ADMIN",
  "current_role": "MEMBER",
  "resource_type": "WORKSPACE"
}
```

## 구현 가이드라인

### 1. 권한 검증 순서
1. 사용자 인증 확인
2. 워크스페이스 멤버십 확인
3. 사용자 역할 확인
4. 요청된 작업에 대한 권한 확인
5. 권한이 없으면 403 Forbidden 응답

### 2. 권한 캐싱
- 사용자 역할 정보는 JWT 토큰에 포함
- 역할 변경 시 토큰 재발급 필요
- 보드별 권한은 데이터베이스에서 조회

### 3. 프론트엔드 권한 처리
- 사용자 역할에 따라 UI 요소 표시/숨김
- 권한이 없는 기능은 비활성화
- 권한 부족 시 적절한 안내 메시지 표시

### 4. 초대 시스템 구현
- 이메일 기반 초대 링크 생성
- 초대 링크의 유효기간 설정 (보통 7일)
- 초대 상태 추적 (대기중, 수락됨, 거부됨)
