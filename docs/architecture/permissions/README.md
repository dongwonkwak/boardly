# 권한 시스템 (Permission System)

## 개요

Boardly의 권한 시스템은 워크스페이스와 보드 레벨에서 멀티테넌시 아키텍처를 기반으로 한 격리된 협업 공간을 제공합니다. 이 시스템은 사용자가 가질 수 있는 역할과 권한을 명확히 정의하여 데이터 보안과 협업 효율성을 보장합니다.

## 문서 구조

### 📋 [워크스페이스 역할 정의](./workspace-roles.md)
워크스페이스 레벨에서의 역할과 권한을 정의합니다.
- **OWNER**: 워크스페이스 소유자 (최고 권한)
- **ADMIN**: 워크스페이스 관리자
- **MEMBER**: 일반 멤버
- 초대 시스템 및 멤버십 관리

### 🔐 [워크스페이스 및 보드 권한 시스템](./workspace-board-permissions.md)
워크스페이스와 보드 권한의 상호작용과 우선순위를 정의합니다.
- 권한 우선순위 규칙
- 보드 역할 (BOARD_ADMIN, BOARD_EDITOR, BOARD_VIEWER)
- 권한 매트릭스
- 보안 고려사항

## 핵심 개념

### 🏢 워크스페이스 (Workspace)
- 협업이 일어나는 가장 큰 단위의 컨테이너
- 멀티테넌시 아키텍처로 완벽한 데이터 격리
- 정식 멤버(Full Member) 시스템

### 📝 보드 (Board)
- 워크스페이스 내 개별 프로젝트 공간
- 공개/비공개 설정 가능
- 세부적인 권한 제어

### 💌 초대 시스템
- **워크스페이스 초대**: 정식 멤버로 가입
- **보드 초대**: 특정 보드에만 접근하는 게스트

### 👑 권한 계층
- **워크스페이스 권한**: 회사 직책과 같은 전체 관리 권한
- **보드 권한**: 프로젝트 실무 역할과 같은 세부 권한
- **권한 우선순위**: 워크스페이스 권한이 보드 권한보다 우선

## 구현 가이드라인

### 권한 검증 순서
1. 사용자 인증 확인
2. 워크스페이스 멤버십 확인
3. 사용자 역할 확인
4. 요청된 작업에 대한 권한 확인
5. 권한이 없으면 403 Forbidden 응답

### 보안 고려사항
- 데이터 격리 (멀티테넌시)
- 권한 상속 및 즉시 적용
- 감사 로그 기록
- 세션 관리
