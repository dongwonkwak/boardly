# US-004 리스트 워크플로 (F-202, P0)

## 배경
리스트는 보드의 단계(예: To Do → Doing → Done)를 표현한다. 사용자는 리스트를 생성·이름/색상 변경·순서 재정렬(드래그 앤 드롭)·삭제하여 자신만의 워크플로를 구성한다.

참조: `PRD.md` F-202, `SRS.md` 3.6, `story_map.md` 4번 백본, 데이터 제약 `SRS.md` 5.

## 사용자 스토리
- (생성) 나는 사용자로서, 보드 내에 새로운 작업 단계를 만들기 위해 리스트를 생성하고 싶다.
- (이름/색상) 나는 사용자로서, 리스트 이름과 색상을 변경해 시각적으로 구분하고 싶다.
- (정렬) 나는 사용자로서, 드래그 앤 드롭으로 리스트 순서를 쉽게 재배치하고 싶다.
- (삭제) 나는 사용자로서, 더 이상 필요 없는 리스트를 삭제하고 싶다.

## 수용 기준 (Acceptance Criteria)
1. 생성
   - 리스트는 특정 보드에 종속된다(필수: `boardId`).
   - `name`은 필수(1~50자). 성공 시 ID, 초기 `position` 반환.
2. 이름/색상 변경
   - `name` 변경 시 유효성 검증(1~50자) 통과해야 한다.
   - `color`는 사전 정의된 팔레트 또는 유효한 HEX 값만 허용(제품 정책에 따름).
3. 순서 변경(드래그 앤 드롭)
   - 사용자는 리스트를 끌어 순서를 변경할 수 있다.
   - 순서 변경 후 모든 관련 리스트의 `position`이 일관되게 갱신·저장된다.
4. 삭제
   - 리스트 삭제 시 성공적으로 제거되고, 보드 뷰에서 즉시 반영된다.
5. 제약
   - 보드당 리스트 수 ≤ 20(`SRS 5`). 초과 생성 시 400 에러.

## 비기능 (NFR)
- 상호작용 반응 ≤ 0.5초, 페이지 로딩 ≤ 2초
- 보안: JWT 인증, 보드 접근 권한 검증
- 사용성: 드래그 앤 드롭 시 시 بص각적 가이드 및 낙관적 업데이트 제공

## 테스트 시나리오 (샘플)
- 생성 성공: 유효 name + boardId → 201/200 + 리소스 반환
- 생성 실패: 리스트 20개 초과 → 400
- 이름/색상 변경 성공/실패(유효성)
- 순서 변경: DnD 후 `position` 재배치가 저장되고 재로딩해도 유지
- 삭제: 성공 시 리스트가 사라지고 보드 내 개수 감소 확인

## 범위
- 포함(P0): 리스트 생성/조회/수정(이름·색상)/삭제, 순서 변경(드래그 앤 드롭)
- 제외: 리스트 간 카드 이동 규칙 상세(카드 관리 스토리에서 다룸)
