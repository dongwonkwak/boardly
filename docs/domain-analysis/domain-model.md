# Boardly 도메인 모델

## 개요
Boardly는 칸반 보드 기반의 프로젝트 관리 서비스로, 워크스페이스, 보드, 카드를 중심으로 한 도메인 모델을 가지고 있습니다.

## 핵심 도메인

### 1. 사용자 (User)
사용자는 Boardly 서비스를 이용하는 개인을 나타냅니다.

#### 속성
- `id`: 사용자 고유 식별자
- `email`: 이메일 주소 (로그인 ID)
- `username`: 사용자명 (로그인용, 고유값)
- `displayName`: 표시명 (화면에 표시되는 이름)
- `profileImage`: 프로필 이미지 URL
- `createdAt`: 가입일시
- `updatedAt`: 정보 수정일시

#### 비즈니스 규칙
- 이메일은 고유해야 한다
- username은 고유해야 한다 (로그인 ID로 사용)
- username은 3-20자 사이여야 하며, 영문자, 숫자, 언더스코어(_)만 사용 가능하다
- username은 대소문자를 구분하지 않는다 (로그인 시)
- displayName은 1-50자 사이여야 한다
- displayName은 중복을 허용한다 (다른 사용자와 같은 표시명 사용 가능)
- displayName은 특수문자, 이모지, 공백을 포함할 수 있다
- 가입 시 개인 워크스페이스가 자동 생성된다
- 사용자는 언제든지 displayName을 변경할 수 있다
- username은 보안상의 이유로 변경이 제한된다 (특별한 경우에만 관리자가 변경 가능)

### 2. 워크스페이스 (Workspace)
프로젝트나 팀이 작업하는 공간을 나타냅니다.

#### 속성
- `id`: 워크스페이스 고유 식별자
- `name`: 워크스페이스 이름
- `description`: 워크스페이스 설명
- `type`: 워크스페이스 타입 (PERSONAL/TEAM)
- `isPublic`: 공개 여부
- `ownerId`: 소유자 사용자 ID
- `createdAt`: 생성일시
- `updatedAt`: 수정일시

#### 비즈니스 규칙
- 워크스페이스 이름은 1-50자 사이여야 한다
- 설명은 최대 200자까지 입력 가능하다
- 개인 워크스페이스는 사용자당 1개씩 자동 생성된다
- 팀 워크스페이스는 무제한으로 생성 가능하다

### 3. 워크스페이스 멤버십 (WorkspaceMembership)
사용자와 워크스페이스 간의 관계를 나타냅니다.

#### 속성
- `id`: 멤버십 고유 식별자
- `userId`: 사용자 ID
- `workspaceId`: 워크스페이스 ID
- `role`: 멤버 역할 (ADMIN/MEMBER)
- `joinedAt`: 가입일시

#### 비즈니스 규칙
- 워크스페이스 생성자는 자동으로 소유자가 되고 ADMIN 권한을 받는다
- 소유자는 다른 ADMIN 멤버에게 소유권을 이전할 수 있다
- 워크스페이스에는 최소 1명의 ADMIN이 있어야 한다
- ADMIN과 소유자만 멤버를 초대/제거할 수 있다
- ADMIN과 소유자만 멤버의 역할을 변경할 수 있다
- 소유자만 워크스페이스를 삭제할 수 있다

#### 역할 정의
- **ADMIN**: 워크스페이스 설정 변경, 멤버 초대/제거, 역할 변경, 모든 보드 생성/수정/삭제
- **MEMBER**: 보드 생성/편집, 카드 관리, 댓글 작성

#### 소유권 관리
- 소유권은 Workspace 테이블의 `ownerId` 필드로 관리
- 소유자는 모든 ADMIN 권한을 가지며 추가로 소유권 이전 및 워크스페이스 삭제 권한 보유

### 4. 보드 (Board)
프로젝트나 작업을 관리하는 단위를 나타냅니다.

#### 속성
- `id`: 보드 고유 식별자
- `title`: 보드 제목
- `description`: 보드 설명
- `workspaceId`: 소속 워크스페이스 ID
- `isPublic`: 공개 여부
- `createdAt`: 생성일시
- `updatedAt`: 수정일시

#### 비즈니스 규칙
- 보드 제목은 1-100자 사이여야 한다
- 보드 설명은 최대 500자까지 입력 가능하다
- 보드는 반드시 하나의 워크스페이스에 속해야 한다
- ADMIN과 MEMBER 모두 보드를 생성할 수 있다

### 5. 컬럼 (Column)
보드 내에서 카드를 분류하는 컬럼을 나타냅니다.

#### 속성
- `id`: 컬럼 고유 식별자
- `name`: 컬럼 이름
- `boardId`: 소속 보드 ID
- `order`: 컬럼 순서
- `createdAt`: 생성일시

#### 비즈니스 규칙
- 컬럼 이름은 1-50자 사이여야 한다
- 보드 생성 시 기본 컬럼이 자동 생성된다 (할 일, 진행중, 완료)
- 컬럼 순서는 변경 가능하다

### 6. 카드 (Card)
실제 작업 항목을 나타냅니다.

#### 속성
- `id`: 카드 고유 식별자
- `title`: 카드 제목
- `description`: 카드 설명
- `columnId`: 소속 컬럼 ID
- `order`: 카드 순서
- `dueDate`: 마감일
- `createdAt`: 생성일시
- `updatedAt`: 수정일시

#### 비즈니스 규칙
- 카드 제목은 1-200자 사이여야 한다
- 카드는 반드시 하나의 컬럼에 속해야 한다
- 카드는 같은 보드 내의 다른 컬럼으로 이동 가능하다
- 카드 순서는 변경 가능하다

### 7. 카드 담당자 (CardAssignee)
카드와 담당자 간의 관계를 나타냅니다.

#### 속성
- `id`: 담당자 할당 고유 식별자
- `cardId`: 카드 ID
- `userId`: 담당자 사용자 ID
- `assignedAt`: 할당일시

#### 비즈니스 규칙
- 카드에는 여러 명의 담당자를 할당할 수 있다
- 담당자는 워크스페이스 멤버 중에서만 선택 가능하다
- 담당자 할당 시 해당 사용자에게 알림이 발송된다

### 8. 댓글 (Comment)
카드에 대한 의견이나 소통을 나타냅니다.

#### 속성
- `id`: 댓글 고유 식별자
- `content`: 댓글 내용
- `cardId`: 소속 카드 ID
- `userId`: 작성자 ID
- `createdAt`: 작성일시
- `updatedAt`: 수정일시

#### 비즈니스 규칙
- 댓글 내용은 1-1000자 사이여야 한다
- 댓글 작성자는 자신의 댓글을 수정/삭제할 수 있다
- 댓글 작성 시 카드 담당자와 보드 멤버에게 알림이 발송된다

### 9. 라벨 (Label)
카드를 분류하기 위한 라벨을 나타냅니다.

#### 속성
- `id`: 라벨 고유 식별자
- `name`: 라벨 이름
- `color`: 라벨 색상
- `boardId`: 소속 보드 ID
- `createdAt`: 생성일시

#### 비즈니스 규칙
- 라벨 이름은 1-20자 사이여야 한다
- 라벨은 보드별로 관리된다
- 카드에는 여러 개의 라벨을 적용할 수 있다

### 10. 체크리스트 (Checklist)
카드 내의 세부 작업 목록을 나타냅니다.

#### 속성
- `id`: 체크리스트 고유 식별자
- `title`: 체크리스트 제목
- `cardId`: 소속 카드 ID
- `order`: 체크리스트 순서
- `createdAt`: 생성일시

#### 비즈니스 규칙
- 체크리스트 제목은 1-100자 사이여야 한다
- 체크리스트는 카드별로 관리된다

### 11. 체크리스트 아이템 (ChecklistItem)
체크리스트의 개별 항목을 나타냅니다.

#### 속성
- `id`: 아이템 고유 식별자
- `content`: 아이템 내용
- `checklistId`: 소속 체크리스트 ID
- `isCompleted`: 완료 여부
- `order`: 아이템 순서
- `createdAt`: 생성일시

#### 비즈니스 규칙
- 아이템 내용은 1-200자 사이여야 한다
- 아이템은 완료/미완료 상태를 가질 수 있다

## 도메인 이벤트

### 1. 워크스페이스 관련 이벤트
- `WorkspaceCreated`: 워크스페이스 생성
- `WorkspaceUpdated`: 워크스페이스 정보 수정
- `WorkspaceDeleted`: 워크스페이스 삭제
- `WorkspaceOwnershipTransferred`: 워크스페이스 소유권 이전
- `MemberInvited`: 멤버 초대
- `MemberJoined`: 멤버 가입
- `MemberRoleChanged`: 멤버 역할 변경
- `MemberRemoved`: 멤버 제거

### 2. 보드 관련 이벤트
- `BoardCreated`: 보드 생성
- `BoardUpdated`: 보드 정보 수정
- `BoardDeleted`: 보드 삭제
- `ColumnCreated`: 컬럼 생성
- `ColumnUpdated`: 컬럼 정보 수정
- `ColumnDeleted`: 컬럼 삭제

### 3. 카드 관련 이벤트
- `CardCreated`: 카드 생성
- `CardUpdated`: 카드 정보 수정
- `CardMoved`: 카드 이동
- `CardDeleted`: 카드 삭제
- `CardAssigned`: 카드 담당자 할당
- `CardUnassigned`: 카드 담당자 해제
- `CommentAdded`: 댓글 추가
- `CommentUpdated`: 댓글 수정
- `CommentDeleted`: 댓글 삭제

## 도메인 서비스

### 1. 권한 검증 서비스 (PermissionService)
- 사용자의 워크스페이스 접근 권한 검증
- 사용자의 보드 수정 권한 검증
- 사용자의 카드 관리 권한 검증

### 2. 알림 서비스 (NotificationService)
- 멤버 초대 알림
- 카드 담당자 할당 알림
- 댓글 작성 알림
- 마감일 알림

### 3. 실시간 협업 서비스 (CollaborationService)
- 실시간 업데이트 브로드캐스팅
- 동시 편집 충돌 방지
- 사용자 활동 추적

## 바운디드 컨텍스트

### 1. 워크스페이스 관리 컨텍스트
- 워크스페이스 생성/수정/삭제
- 멤버 관리
- 권한 관리

### 2. 보드 관리 컨텍스트
- 보드 생성/수정/삭제
- 컬럼 관리
- 보드 설정

### 3. 카드 관리 컨텍스트
- 카드 생성/수정/삭제
- 카드 이동
- 담당자 할당

### 4. 협업 컨텍스트
- 댓글 관리
- 실시간 협업
- 알림 관리

### 5. 사용자 관리 컨텍스트
- 사용자 등록/수정
- 인증/인가
- 프로필 관리
