# 협업 기능 유저스토리

## Epic: 협업 기능
**목표**: 사용자들이 팀으로 협업하여 보드와 카드를 함께 관리할 수 있다.

---

## User Story 1: 팀원 초대하기

**As a** 워크스페이스 ADMIN  
**I want to** 팀원을 워크스페이스에 초대할 수 있다  
**So that** 팀원들과 함께 프로젝트를 관리할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 워크스페이스 설정 페이지에 있다  
**When** "팀원 초대" 버튼을 클릭한다  
**Then** 팀원 초대 모달이 열린다

**Given** 팀원 초대 모달이 열려있다  
**When** 이메일 주소를 입력한다  
**And** 권한 레벨을 선택한다 (관리자/편집자/뷰어)  
**And** "초대 보내기" 버튼을 클릭한다  
**Then** 초대 이메일이 발송된다  
**And** "초대가 발송되었습니다" 메시지가 표시된다

#### 비즈니스 규칙
- 워크스페이스 ADMIN만 팀원을 초대할 수 있다
- 초대된 사용자는 이메일을 통해 초대를 수락할 수 있다
- 초대는 7일간 유효하다
- 같은 이메일로 중복 초대는 불가능하다

#### 역할 레벨
- **ADMIN**: 워크스페이스 설정 변경, 멤버 초대/제거, 역할 변경, 모든 보드 생성/수정/삭제
- **MEMBER**: 보드 생성/편집, 카드 관리, 댓글 작성

#### 예외 상황
**Given** 팀원 초대 모달이 열려있다  
**When** 잘못된 이메일 형식을 입력한다  
**And** "초대 보내기" 버튼을 클릭한다  
**Then** "올바른 이메일 형식을 입력해주세요" 오류 메시지가 표시된다

**Given** 팀원 초대 모달이 열려있다  
**When** 이미 초대된 이메일을 입력한다  
**And** "초대 보내기" 버튼을 클릭한다  
**Then** "이미 초대된 사용자입니다" 오류 메시지가 표시된다

#### 테스트 시나리오
1. **정상 초대**: 올바른 이메일로 팀원 초대
2. **잘못된 이메일**: 잘못된 형식의 이메일 입력
3. **중복 초대**: 이미 초대된 사용자 재초대 시도
4. **권한 확인**: ADMIN이 아닌 사용자의 초대 시도
5. **초대 만료**: 7일 후 초대 링크 만료 확인

## User Story 2: 카드 담당자 할당하기

**As a** 보드 사용자  
**I want to** 카드에 담당자를 할당할 수 있다  
**So that** 누가 어떤 작업을 담당하는지 명확히 할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 카드 상세 모달에 있다  
**When** "담당자" 섹션의 "담당자 추가" 버튼을 클릭한다  
**Then** 워크스페이스 멤버 목록이 표시된다

**Given** 워크스페이스 멤버 목록이 표시되어 있다  
**When** 특정 멤버를 선택한다  
**Then** 해당 멤버가 카드 담당자로 할당된다  
**And** 카드에 담당자 아바타가 표시된다

#### 비즈니스 규칙
- 카드에는 여러 명의 담당자를 할당할 수 있다
- 담당자는 워크스페이스 멤버 중에서만 선택 가능하다
- 담당자 할당 시 해당 사용자에게 알림이 발송된다
- 담당자는 언제든지 제거할 수 있다

#### 예외 상황
**Given** 사용자가 카드 상세 모달에 있다  
**When** 워크스페이스에 멤버가 없는 상태에서 "담당자 추가"를 클릭한다  
**Then** "초대할 팀원이 없습니다" 메시지가 표시된다

#### 테스트 시나리오
1. **담당자 할당**: 워크스페이스 멤버를 카드 담당자로 할당
2. **다중 담당자**: 여러 명의 담당자 할당
3. **담당자 제거**: 할당된 담당자 제거
4. **알림 발송**: 담당자 할당 시 알림 확인
5. **권한 확인**: MEMBER 권한이 없는 사용자의 담당자 할당 시도

## User Story 3: 댓글 작성하기

**As a** 보드 사용자  
**I want to** 카드에 댓글을 작성할 수 있다  
**So that** 팀원들과 의견을 나누고 소통할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 카드 상세 모달에 있다  
**When** 댓글 입력 필드에 텍스트를 입력한다  
**And** "댓글 작성" 버튼을 클릭한다  
**Then** 댓글이 카드에 추가된다  
**And** 작성자, 작성 시간, 댓글 내용이 표시된다

#### 비즈니스 규칙
- 댓글은 최대 1000자까지 작성 가능하다
- 댓글 작성자는 자신의 댓글을 수정/삭제할 수 있다
- 댓글 작성 시 카드 담당자와 보드 멤버에게 알림이 발송된다
- 댓글은 시간순으로 정렬되어 표시된다

#### 예외 상황
**Given** 사용자가 카드 상세 모달에 있다  
**When** 빈 댓글을 작성하려고 한다  
**Then** "댓글 내용을 입력해주세요" 오류 메시지가 표시된다

**Given** 사용자가 카드 상세 모달에 있다  
**When** 1000자를 초과하는 댓글을 작성하려고 한다  
**Then** "댓글은 1000자 이하여야 합니다" 오류 메시지가 표시된다

#### 테스트 시나리오
1. **댓글 작성**: 정상적인 댓글 작성
2. **빈 댓글**: 내용 없는 댓글 작성 시도
3. **긴 댓글**: 1000자 초과 댓글 작성 시도
4. **댓글 수정**: 작성한 댓글 수정
5. **댓글 삭제**: 작성한 댓글 삭제
6. **알림 발송**: 댓글 작성 시 알림 확인

## User Story 4: 실시간 협업

**As a** 보드 사용자  
**I want to** 다른 팀원의 활동을 실시간으로 확인할 수 있다  
**So that** 팀원들과 동시에 작업할 수 있다

### 수용기준 (Acceptance Criteria)

#### 기본 플로우
**Given** 사용자가 보드 페이지에 있다  
**When** 다른 팀원이 카드를 이동시킨다  
**Then** 카드 이동이 실시간으로 반영된다  
**And** "김철수가 '카드명'을 '진행중'으로 이동했습니다" 알림이 표시된다

**Given** 사용자가 보드 페이지에 있다  
**When** 다른 팀원이 카드를 편집한다  
**Then** 카드 내용 변경이 실시간으로 반영된다

#### 비즈니스 규칙
- 실시간 업데이트는 WebSocket을 통해 처리된다
- 사용자 활동은 5초 후 자동으로 사라진다
- 현재 접속 중인 팀원 목록이 표시된다
- 동시 편집 시 충돌 방지 메커니즘이 작동한다

#### 테스트 시나리오
1. **실시간 카드 이동**: 다른 사용자의 카드 이동 실시간 반영
2. **실시간 카드 편집**: 다른 사용자의 카드 편집 실시간 반영
3. **실시간 댓글**: 다른 사용자의 댓글 실시간 표시
4. **접속자 표시**: 현재 접속 중인 팀원 목록 확인
5. **동시 편집**: 여러 사용자의 동시 편집 처리
