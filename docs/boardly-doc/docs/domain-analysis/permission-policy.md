# Boardly 권한 정책

## 개요
Boardly의 권한 시스템은 역할 기반 접근 제어(RBAC)를 기반으로 하며, 워크스페이스 단위로 권한이 관리됩니다.

## 권한 모델

### 워크스페이스 권한

#### 소유권과 권한의 분리
- **소유권**: Workspace 테이블의 `ownerId` 필드로 관리되는 소유권
- **권한**: WorkspaceMembership 테이블의 `role` 필드로 관리되는 역할 기반 권한

#### ADMIN
워크스페이스의 관리자 역할로, 대부분의 권한을 가집니다.

**권한 목록:**
- 워크스페이스 설정 변경
- 멤버 초대/제거
- 멤버 역할 변경
- 모든 보드 생성/수정/삭제
- 모든 보드 멤버 관리
- 모든 카드 관리
- 모든 댓글 관리

#### MEMBER
워크스페이스의 일반 멤버 역할로, 제한된 권한을 가집니다.

**권한 목록:**
- 보드 생성/편집
- 카드 생성/편집/삭제
- 카드 이동
- 댓글 작성/수정/삭제
- 담당자 할당

#### 소유자의 특별 권한
워크스페이스 소유자(`ownerId`)는 ADMIN 권한과 함께 추가로 다음 권한을 가집니다:

**추가 권한 목록:**
- 워크스페이스 삭제
- 소유권 이전 (다른 ADMIN 멤버에게)

### 보드 권한

#### ADMIN
보드의 관리자 역할로, 모든 권한을 가집니다.

**권한 목록:**
- 보드 정보 수정/삭제
- 보드 멤버 초대/제거/역할 변경
- 보드 공개/비공개 설정
- 모든 리스트 관리
- 모든 카드 관리
- 모든 댓글 관리
- 라벨 생성/수정/삭제

#### MEMBER
보드의 편집자 역할로, 제한된 권한을 가집니다.

**권한 목록:**
- 보드 정보 수정
- 리스트 추가/수정/삭제
- 카드 생성/수정/삭제
- 카드 이동
- 댓글 작성/수정/삭제
- 담당자 할당
- 라벨 생성/수정

#### VIEWER
보드의 조회자 역할로, 읽기 전용 권한을 가집니다.

**권한 목록:**
- 보드 조회
- 리스트 조회
- 카드 내용 조회
- 댓글 조회

## 권한 정책 규칙

### 1. 워크스페이스 권한 규칙
- 워크스페이스를 생성한 사용자는 자동으로 소유자(`ownerId`)가 되고 ADMIN 역할을 받는다
- 소유자는 워크스페이스에 대한 ADMIN 권한과 모든 보드에 대한 ADMIN 권한을 가진다
- 소유자는 소유권 이전을 통해 다른 ADMIN 멤버에게 소유권을 이전할 수 있다
- 소유권 이전 후 이전 소유자는 새로운 역할(ADMIN/MEMBER)을 선택할 수 있다
- 동일한 사용자는 같은 워크스페이스 이름을 가질 수 없다
- 워크스페이스에는 최소 1명의 ADMIN이 있어야 한다
- 마지막 ADMIN의 역할을 MEMBER로 변경할 수 없다
- 소유자가 아닌 마지막 ADMIN은 자신의 역할을 변경할 수 없다
- 워크스페이스 ADMIN은 모든 보드의 모든 권한을 가진다

### 2. 보드 권한 규칙
- 보드 생성 시 사용자의 워크스페이스 역할이 보드 권한으로 상속된다
- 워크스페이스 ADMIN이 보드를 생성하면 해당 보드의 ADMIN 권한을 가진다
- 워크스페이스 MEMBER가 보드를 생성하면 해당 보드의 MEMBER 권한을 가진다
- 워크스페이스 소유자는 모든 보드에 대해 ADMIN 권한을 가진다
- 보드에는 최소 1명의 ADMIN이 있어야 한다
- 보드 ADMIN은 자신의 역할을 변경할 수 있다
- 워크스페이스 ADMIN은 보드 멤버에게 ADMIN 권한을 부여할 수 있다

### 3. 공개/비공개 보드 규칙
- 공개 보드: 워크스페이스 멤버가 자동으로 EDITOR 권한을 가진다
- 비공개 보드: 초대받은 사용자만 접근 가능하다
- 보드 생성 시 공개/비공개 여부를 설정할 수 있다

### 4. 초대 시스템 규칙
- 외부/내부 사용자에게 특정 보드에 초대할 수 있다
- 초대 시 보드 권한(MEMBER/VIEWER)을 지정할 수 있다 (ADMIN 권한은 지정 불가)
- 초대 링크를 생성하여 이메일로 발송하거나 링크를 복사하여 공유할 수 있다
- 초대받은 사용자가 회원가입을 하지 않았다면 회원가입이 필수이다
- 초대 만료 기간은 설정 가능하며, 기본값은 7일이다
- 초대받은 사용자는 해당 보드가 속한 워크스페이스 권한이 없다

### 5. 권한 상속 및 전파
- 워크스페이스에서 멤버가 제거되면 해당 보드에서도 자동으로 제거된다
- 워크스페이스 권한이 보드 권한보다 우선순위가 높다

### 6. 데이터 관리 규칙
- 보드 삭제 시 포함된 모든 데이터가 자동으로 삭제된다
- 라벨 삭제 시 할당된 카드가 있으면 경고 메시지를 표시하고 사용자 확인 후 삭제한다
- 라벨 삭제 시 카드는 유지되고 라벨만 제거된다

### 7. 소유권 이전 규칙
- 워크스페이스 소유자만 소유권을 이전할 수 있다
- 소유권은 워크스페이스 멤버 중 ADMIN 역할을 가진 멤버에게만 이전 가능하다
- 워크스페이스 멤버가 1명인 경우 소유권 이전이 불가능하다
- 소유권 이전 시 이중 확인 절차가 필요하다
- 소유권 이전 시 소유자의 비밀번호 재입력이 필요하다
- 소유권 이전 시 모든 멤버에게 알림이 발송된다
- 소유권 이전 이력은 영구적으로 기록된다

### 8. 권한 검증
- 모든 작업 전에 사용자의 권한을 검증한다
- 권한이 없는 작업 시도 시 적절한 오류 메시지를 반환한다

## 권한 검증 구현

### 1. 권한 검증 서비스
```typescript
interface PermissionService {
  // 워크스페이스 권한
  canManageWorkspace(userId: string, workspaceId: string): boolean;
  canInviteMember(userId: string, workspaceId: string): boolean;
  canRemoveMember(userId: string, workspaceId: string): boolean;
  canChangeMemberRole(userId: string, workspaceId: string): boolean;
  
  // 보드 권한
  canManageBoard(userId: string, boardId: string): boolean;
  canEditBoard(userId: string, boardId: string): boolean;
  canViewBoard(userId: string, boardId: string): boolean;
  canInviteBoardMember(userId: string, boardId: string): boolean;
  canRemoveBoardMember(userId: string, boardId: string): boolean;
  canChangeBoardMemberRole(userId: string, boardId: string): boolean;
  
  // 카드 권한
  canManageCard(userId: string, cardId: string): boolean;
  canEditCard(userId: string, cardId: string): boolean;
  canViewCard(userId: string, cardId: string): boolean;
  
  // 댓글 권한
  canManageComment(userId: string, commentId: string): boolean;
  canEditComment(userId: string, commentId: string): boolean;
  
  // 라벨 권한
  canManageLabel(userId: string, boardId: string): boolean;
  canEditLabel(userId: string, boardId: string): boolean;
}
```

### 2. 권한 검증 미들웨어
- API 요청 시 자동으로 권한을 검증
- 권한이 없는 경우 403 Forbidden 응답
- 적절한 오류 메시지와 함께 응답

### 3. 프론트엔드 권한 처리
- 권한에 따라 UI 요소 표시/숨김
- 권한이 없는 기능에 대한 안내 메시지
- 권한 상승을 위한 관리자 문의 안내

## 보안 고려사항

### 1. 서버 사이드 검증
- 모든 권한 검증은 서버에서 수행
- 클라이언트 사이드 검증은 UI/UX 목적으로만 사용

### 2. 세션 관리
- 사용자 세션에 권한 정보 포함
- 권한 변경 시 세션 갱신

### 3. 감사 로그
- 권한 관련 작업에 대한 감사 로그 기록
- 권한 변경 이력 추적

## 특별 고려사항

### 1. 라벨 관리
- 라벨 이름 중복은 보드 내에서만 체크한다
- 라벨 색상은 미리 정의된 팔레트에서만 선택 가능하다
- 라벨 삭제 시 할당된 카드가 있으면 경고 메시지를 표시하고 사용자 확인 후 삭제한다

### 2. 보드 공개/비공개
- 공개 보드: 워크스페이스 멤버가 자동으로 EDITOR 권한을 가진다
- 비공개 보드: 워크스페이스에서 보드가 보이지 않으며, 초대받은 사용자만 접근 가능하다

### 3. 초대 시스템
- 외부/내부 사용자에게 특정 보드에 초대할 수 있다
- 초대 시 보드 권한(MEMBER/VIEWER)을 지정할 수 있다 (ADMIN 권한은 지정 불가)
- 초대 링크를 생성하여 이메일로 발송하거나 링크를 복사하여 공유할 수 있다
- 초대받은 사용자가 회원가입을 하지 않았다면 회원가입이 필수이다
- 초대 만료 기간은 설정 가능하며, 기본값은 7일이다
- 초대받은 사용자는 해당 보드가 속한 워크스페이스 권한이 없다
- 로그인 시 초대 알림과 "보드로 바로 가기" 버튼을 제공한다
- 메인 대시보드에 "게스트 워크스페이스" 섹션이 존재하여 초대받은 보드 목록을 볼 수 있다

## 향후 확장 계획

### 1. 세분화된 권한
- 현재 2단계 권한 체계에서 더 세분화된 권한 체계로 확장 가능
- 예: 카드별 권한, 컬럼별 권한 등

### 2. 권한 그룹
- 여러 권한을 묶어서 그룹으로 관리
- 예: "개발자 그룹", "디자이너 그룹" 등

### 3. 조건부 권한
- 특정 조건에 따른 권한 부여
- 예: 프로젝트 진행률에 따른 권한 차등 부여
