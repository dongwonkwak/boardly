# US-SEC-004: Rate Limiting `[P0]`

**As a** 사용자  
**I want to** 시스템이 남용으로부터 보호되어  
**So that** 안정적인 서비스를 이용하고 싶다.

## Scenarios

### ✅ 성공 케이스 - API 요청 제한
```gherkin
Given 사용자가 정상적인 속도로 API를 호출할 때
When 분당 100회 이하의 요청을 보내면
Then 모든 요청이 정상 처리되고
And 응답 헤더에 남은 요청 수가 표시된다
```

### ❌ 실패 케이스 - 요청 제한 초과
```gherkin
Given 사용자나 공격자가 과도한 API 요청을 보낼 때
When 분당 100회를 초과하는 요청이 발생하면
Then 429 Too Many Requests 응답이 반환되고
And "요청 한도를 초과했습니다. 잠시 후 다시 시도해주세요" 메시지가 표시되고
And 일정 시간 후 제한이 해제된다
```

### ✅ 성공 케이스 - 브루트 포스 방어
```gherkin
Given 공격자가 로그인 시도를 반복할 때
When 동일 IP에서 5회 연속 로그인 실패가 발생하면
Then 해당 IP가 15분간 로그인 차단되고
And "보안을 위해 일시적으로 로그인이 제한되었습니다" 메시지가 표시되고
And 보안 로그에 공격 시도가 기록된다
```

### ✅ 성공 케이스 - 점진적 제한 강화
```gherkin
Given 사용자가 제한에 근접할 때
When 남은 요청 수가 10개 이하가 되면
Then 응답 헤더에 경고가 포함되고
And 클라이언트에서 요청 속도를 조절할 수 있는 안내가 제공된다
```

**Priority:** High | **Story Points:** 5
