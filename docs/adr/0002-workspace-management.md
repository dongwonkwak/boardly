# ADR 0002: 워크스페이스 관리 및 멀티테넌시

- 상태: 승인됨
- 날짜: 2025-08-18

## 문맥(Context)
- Boardly는 멀티테넌트 환경에서 사용자가 여러 워크스페이스에 속할 수 있습니다.
- 사용자는 요청마다 활성 워크스페이스를 전환할 수 있어야 합니다.
- 워크스페이스별로 독립적인 보드, 멤버, 권한 관리가 필요합니다.
- 개인보드와 워크스페이스 보드를 구분하여 관리해야 합니다.

## 결정(Decision)
워크스페이스 기반 멀티테넌시 아키텍처를 채택합니다.

### 워크스페이스 식별 및 전환
- **활성 워크스페이스 지정**: 요청 헤더 `X-Workspace-Id` 또는 URL/path 파라미터로 전달
- **기본 워크스페이스**: 사용자가 속한 첫 번째 워크스페이스 또는 개인 워크스페이스
- **워크스페이스 전환**: 토큰 재발급 없이 헤더만 변경하여 즉시 전환 가능

### 워크스페이스 구조
```json
{
  "workspace_id": "ws_123",
  "name": "프로젝트 A팀",
  "description": "A팀 프로젝트 관리",
  "type": "TEAM", // TEAM, PERSONAL
  "owner_id": "user_456",
  "created_at": "2025-01-27T10:00:00Z",
  "settings": {
    "visibility": "PRIVATE", // PRIVATE, PUBLIC
    "allow_guest_access": false,
    "default_board_template": "kanban"
  }
}
```

### 워크스페이스 멤버십
```json
{
  "workspace_id": "ws_123",
  "user_id": "user_789",
  "role": "MEMBER", // OWNER, ADMIN, MEMBER, GUEST
  "joined_at": "2025-01-27T10:00:00Z",
  "permissions": {
    "create_board": true,
    "invite_members": false,
    "manage_workspace": false
  }
}
```

**역할 및 권한 상세 정의는 [워크스페이스 역할 정의 문서](../workspace-roles.md)를 참조합니다.**

### 보드 관리
- **워크스페이스 보드**: 워크스페이스 내에서 생성된 공유 보드
- **개인보드**: 사용자 개인이 소유하는 개인 보드
- **보드 식별**: `X-Board-Id` 헤더로 보드 지정

## 결과(Consequences)
- 장점:
  - 명확한 리소스 격리 및 보안 경계
  - 워크스페이스별 독립적인 설정 및 커스터마이징
  - 확장 가능한 멀티테넌트 아키텍처
  - 사용자 경험 향상 (빠른 워크스페이스 전환)
- 단점:
  - 각 요청에서 `X-Workspace-Id` 헤더 처리 필요
  - 워크스페이스별 데이터 분리로 인한 복잡성 증가
  - 크로스 워크스페이스 기능 구현 시 추가 복잡성
- 요구사항:
  - 워크스페이스별 데이터베이스 스키마 설계
  - 워크스페이스 전환 시 UI 상태 관리
  - 워크스페이스별 리소스 사용량 모니터링

## 고려한 대안(Alternatives)
- **단일 테넌트**: 기각 - 확장성 및 보안 격리 부족
- **조직 기반**: 기각 - 현재 범위에 과도한 복잡성
- **프로젝트 기반**: 기각 - 워크스페이스가 더 적절한 추상화 수준

## 후속 작업(Follow-ups)
- 워크스페이스 CRUD API 설계 및 구현
- 워크스페이스 멤버십 관리 API 구현
- 워크스페이스별 보드 관리 로직 구현
- 개인보드와 워크스페이스 보드 구분 로직 구현
- 워크스페이스 전환 시 UI 상태 관리 구현
- 워크스페이스별 리소스 사용량 추적 시스템 구축
