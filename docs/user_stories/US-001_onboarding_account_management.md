# US-001 온보딩·계정 관리 (F-101, P0)

## 배경
Boardly의 첫 경험은 계정 생성과 안전한 접근에서 시작된다. 사용자는 이메일/비밀번호로 가입·로그인하고, 프로필 및 비밀번호를 관리하며, 선호 언어를 설정할 수 있어야 한다.

참조: `PRD.md` F-101, `SRS.md` 3.1, 6.5, `story_map.md` 1번 백본

## 사용자 스토리
- (가입) 나는 신규 사용자로서, 유효한 이메일과 강력한 비밀번호로 쉽게 회원가입하고 싶다.
- (로그인/로그아웃) 나는 사용자로서, 이메일/비밀번호로 로그인/로그아웃하여 내 리소스에 안전하게 접근하고 싶다.
- (프로필 관리) 나는 사용자로서, 내 이름/언어 등 프로필 정보를 조회·수정하고 싶다.
- (비밀번호 변경) 나는 사용자로서, 보안을 위해 비밀번호를 정책에 맞게 변경하고 싶다.
- (언어 설정) 나는 사용자로서, 한국어/영어 중 선호 언어로 UI를 사용하고 필요 시 즉시 전환하고 싶다.

## 수용 기준 (Acceptance Criteria)
1. 회원가입
   - 비밀번호는 최소 8자이며 대문자/소문자/특수문자를 각각 최소 1자 포함해야 한다.
   - firstName/lastName은 1~50자, 한글/영문만 허용한다.
   - 유효 입력 시 계정이 생성되고 성공 응답이 반환된다.
2. 로그인/로그아웃
   - 올바른 이메일/비밀번호 입력 시 JWT가 발급되고 보호 API 접근이 가능하다.
   - 로그아웃 시 토큰이 무효화되거나 클라이언트 저장소에서 제거된다.
3. 프로필 관리
   - 사용자는 firstName/lastName/language를 조회·수정할 수 있다.
   - 유효성 오류 시 필드별 메시지가 표시된다.
4. 비밀번호 변경
   - 현재 비밀번호 검증 후 새 비밀번호 규칙을 만족해야 변경된다.
5. 언어 설정
   - 최초 접속 시 브라우저 언어를 기본값으로 설정한다.
   - 사용자가 언어를 전환하면 전체 UI 텍스트가 즉시 해당 언어로 렌더링된다.

## 비기능 (NFR)
- 초기 페이지 로딩 ≤ 2초, 상호작용 반응 ≤ 0.5초
- 보안: BCrypt 해시 저장, JWT 인증, CSRF/XSS/SQLi 대응, Rate Limiting
- i18n: i18next(프론트), MessageSource(백엔드) 기반, 동적 전환 지원

## 테스트 시나리오 (샘플)
- 성공 가입: 유효 입력 → 201/200 응답, DB에 사용자 생성됨
- 실패 가입: 약한 비밀번호 → 400과 규칙 위반 메시지
- 로그인 성공 → JWT 저장, 보호 API 200
- 로그인 실패 → 401
- 프로필 수정 성공/실패(유효성)
- 비밀번호 변경 성공/실패(현재 비밀번호 불일치, 규칙 미준수)
- 언어 전환 → 텍스트 리소스가 선택 언어로 즉시 변경

## 범위
- 포함: 회원가입, 로그인/로그아웃, 프로필 조회·수정, 비밀번호 변경, 언어 설정
- 제외: 소셜 로그인(Px), 이메일 인증(Px), 2FA(Px)
