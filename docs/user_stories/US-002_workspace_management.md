# US-002 워크스페이스 구성 (F-150, P0)

## 배경
사용자는 개인/팀 활동을 분리하고, 관련 보드를 한 곳에서 관리하기 위해 워크스페이스를 사용한다. 워크스페이스는 보드들의 최상위 컨테이너이며 타입(Personal/Team)을 가진다.

참조: `PRD.md` F-150, `SRS.md` 3.2, `workspace.md`, `story_map.md` 2번 백본, 삭제 정책 `SRS.md` 3.10.1, 데이터 제약 `SRS.md`

## 사용자 스토리
- (생성) 나는 사용자로서, 프로젝트 성격에 맞게 Personal 또는 Team 타입의 워크스페이스를 생성하고 싶다.
- (목록/조회) 나는 사용자로서, 내가 소유하거나 참여 중인 워크스페이스 목록과 상세 정보를 보고 싶다.
- (수정) 나는 사용자로서, 워크스페이스 이름/설명/타입을 수정하고 싶다.
- (삭제) 나는 워크스페이스 OWNER로서, 사전 조건을 충족할 때만 워크스페이스를 안전하게 삭제하고 싶다.
- (권한) 나는 워크스페이스 OWNER로서, 멀티테넌시 아키텍처로 완전히 격리된 공간을 관리하고 싶다.
- (Personal 워크스페이스) 나는 개인 프로젝트를 위해 Personal 워크스페이스를 생성하고 싶다.
- (Team 워크스페이스) 나는 팀 협업을 위해 Team 워크스페이스를 생성하고 싶다.

## 수용 기준 (Acceptance Criteria)
1. 생성
   - 워크스페이스 `name`은 필수(1~100자)이고 중복 허용(소유자 범위 내 고유성은 선택)이다.
   - `type`은 `PERSONAL` 또는 `TEAM`만 허용한다.
   - 성공 시 워크스페이스 ID, 생성 시각을 포함한 응답을 반환한다.
   - 생성자는 자동으로 OWNER 역할을 가진다.
   - Personal 워크스페이스: 개인 전용, 멤버 초대 불가, 사용자 혼자만 접근 가능
   - Team 워크스페이스: 멤버 초대 및 협업 가능, 보드 공개/비공개 설정 지원
2. 조회
   - 사용자는 자신이 소유하거나 참여 중(P1)인 워크스페이스만 조회할 수 있다.
   - 목록은 페이지네이션/정렬(이름, 최근 업데이트) 옵션을 지원한다(선택).
3. 수정
   - OWNER만 수정 가능. 유효성 검증 실패 시 필드별 에러 메시지 제공.
4. 삭제 (가드)
   - OWNER만 삭제 가능.
   - 사전 조건: 워크스페이스 내 모든 보드가 먼저 삭제되어야 한다(`SRS 3.10.1`).
   - 확인 절차: 워크스페이스명을 정확히 입력해야 삭제가 확정된다.
5. 제약
   - 사용자는 최대 10개 워크스페이스까지 생성 가능(`SRS 5. 데이터 제약`). 초과 시 400 에러.
6. 멀티테넌시
   - 워크스페이스 간 완전한 데이터 격리 보장.
   - 각 워크스페이스는 독립적인 권한 체계를 가진다.

## 비기능 (NFR)
- 성능: 목록 조회 응답 ≤ 500ms, 생성/수정/삭제 ≤ 800ms
- 보안: JWT 인증 필수, 권한 검증(OWNER만 수정/삭제), 멀티테넌시 데이터 격리
- 사용성: 삭제 확인 모달에 워크스페이스명 입력 필드 제공

## 테스트 시나리오 (샘플)
- 생성 성공: 유효 name/type → 201/200 + 리소스 반환, OWNER 역할 자동 부여
- 생성 실패: type=INVALID → 400
- 목록 조회: 자신의 워크스페이스만 N개 반환, 페이지네이션 동작
- 수정 성공/실패: OWNER가 아닌 사용자 수정 시도 → 403
- 삭제 가드: 보드 존재 시 삭제 시도 → 409(또는 400) + 안내 메시지
- 삭제 성공: 이름 확인 일치 → 200, 리소스 제거 확인
- 멀티테넌시: 다른 워크스페이스 데이터 접근 시도 → 404

## 범위
- 포함(P0): 워크스페이스 생성/조회/수정/삭제, 타입(Personal/Team), 생성 개수 제한
- 제외(P1): 멤버 초대/역할, 접근제어 매트릭스, 활동 통합
