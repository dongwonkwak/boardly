# Roadmap — Boardly

프로젝트의 개발 단계별 목표와 주요 Epic을 정리한 문서입니다. 각 Epic은 Epic & Issues 문서와 연결되며, 사이클 계획의 근거가 됩니다. 다국어(i18n)는 모든 단계에서 기본 고려사항으로 적용됩니다. 풀스택 개발(Backend + Frontend + Integration)에 최적화되어 있습니다.

---

## Phase 1 (MVP 1) — 사용자 인증/인가

**개발 기간**: 2주 (Cycle 1)
**완성도**: 사용자가 실제 로그인할 수 있는 완전한 인증 시스템

### Backend 개발

* 회원가입 API 구현 (다국어 에러/검증 메시지 적용)
* 로그인 API 구현 (JWT 토큰 발급, 다국어 에러 응답 적용)
* Refresh Token 갱신 처리
* 사용자 Entity 및 Repository 설계
* Spring Security 통합 및 JWT 필터 구현

### Frontend 개발

* 회원가입 페이지 UI 구현 (Ant Design 기반)
* 로그인 페이지 UI 구현 (폼 validation 포함)
* 인증 상태 관리 (Context API + React Query)
* 토큰 저장 및 자동 갱신 로직
* 라우팅 가드 (인증 필요 페이지 보호)

### Integration

* 회원가입/로그인 E2E 테스트 (Playwright)
* API 연동 통합 테스트
* 토큰 만료/갱신 시나리오 테스트
* 다국어 에러 메시지 표시 테스트

## Phase 2 (MVP 2) — 워크스페이스 & 보드 관리

**개발 기간**: 4주 (Cycle 2-3)
**완성도**: 팀 기반 워크스페이스와 보드를 생성하고 관리할 수 있는 완전한 시스템

### Backend 개발

* 워크스페이스 생성/조회/수정/삭제 API
* 워크스페이스 멤버 초대 및 권한(Role: OWNER/MEMBER/GUEST) 관리
* 보드 생성/조회/수정/삭제 API
* 보드 멤버 초대 및 권한(Role: ADMIN/MEMBER/VIEWER) 관리
* **이메일 초대 전송 시스템 (워크스페이스/보드)**
* **초대 수락/만료/취소/재전송 플로우**
* **활동 로그 / 감사 로그 (워크스페이스/보드 단위 변경 추적)**
* RBAC 기반 API 보안 및 권한 검증
* 모든 권한 관련 에러/응답 메시지에 다국어 적용

### Frontend 개발

* 워크스페이스 목록/생성 UI 구현 (대시보드 페이지)
* 워크스페이스 설정 및 멤버 관리 UI
* 보드 목록/생성 UI 구현 (워크스페이스 내)
* 보드 설정 및 멤버 관리 UI
* 멤버 초대 모달 및 권한 설정 UI
* 초대 링크 공유 및 수락 페이지
* 활동 로그 피드 UI 구현
* 권한별 UI 표시/숨김 제어 로직

### Integration

* 워크스페이스/보드 생성 E2E 테스트
* 멤버 초대 플로우 E2E 테스트 (이메일 발송 포함)
* 권한별 접근 제어 E2E 테스트
* 활동 로그 기록 및 표시 통합 테스트
* 다국어 권한 메시지 표시 테스트

## Phase 3 (MVP 3) — 카드/리스트 관리

**개발 기간**: 3주 (Cycle 4)
**완성도**: 트렐로와 같은 칸반 보드 기능이 완전히 작동하는 시스템

### Backend 개발

* 리스트 생성/수정/삭제 API (순서 관리 포함)
* 카드 생성/수정/삭제 API (상세 정보 포함)
* 카드 드래그&드롭 이동 처리 API (리스트 간, 순서 변경)
* 카드 상세 조회 API (댓글/첨부 포함)
* **댓글 시스템 구현 (CRUD, 멘션 기능)**
* **파일 업로드/첨부 기능 (S3/Cloud Storage 연동)**
* **검색/필터링 API (키워드, 라벨, 담당자 단위)**
* WebSocket을 통한 실시간 업데이트 시스템
* 카드/리스트 관련 메시지 및 에러 다국어 적용

### Frontend 개발

* 칸반 보드 UI 구현 (리스트와 카드 레이아웃)
* 리스트 CRUD UI 구현
* 카드 CRUD UI 구현 (상세 모달 포함)
* 드래그앤드롭 구현 (@dnd-kit 라이브러리 활용)
* 댓글 컴포넌트 구현 (작성, 수정, 삭제, 멘션)
* 파일 첨부 컴포넌트 구현 (드래그앤드롭 업로드)
* 검색/필터 UI 구현 (검색바, 필터 옵션, 자동완성)
* WebSocket 연결 및 실시간 업데이트 처리
* 낙관적 UI 업데이트 및 충돌 해결

### Integration

* 칸반 보드 기본 기능 E2E 테스트
* 드래그앤드롭 시나리오 E2E 테스트
* 실시간 협업 시나리오 테스트 (다중 사용자)
* 파일 업로드/다운로드 E2E 테스트
* 검색/필터링 기능 E2E 테스트
* WebSocket 연결 안정성 및 재연결 테스트

## Phase 4 (MVP 4) — i18n 확장 & 알림 시스템

**개발 기간**: 2주 (Cycle 5)
**완성도**: 다국어 지원과 실시간 알림이 완비된 상용 수준의 시스템

### Backend 개발

* 사용자 언어 전환 기능 (프로필 설정, 쿠키/스토리지 기반 저장)
* 다국어 리소스 관리 및 배포 전략
* 에러 메시지/도메인 메시지 전체 번역 범위 확대
* **알림(Notification) 시스템 구현**

  * 이메일 알림 API (초대/카드 배정/댓글 멘션 등)
  * In-App Notification API (실시간 알림)
  * 알림 설정 관리 API (사용자별 알림 on/off)
* 번역 키 자동 추출 및 관리 도구
* 프론트엔드/백엔드 간 i18n 동기화 강화

### Frontend 개발

* 언어 선택 컴포넌트 및 언어 전환 UI
* React i18n 라이브러리 통합 (react-i18next)
* 번역 파일 동적 로딩 및 캐싱
* 알림 센터 UI 구현 (토스트, 배지, 알림 목록)
* 알림 설정 페이지 구현
* 실시간 알림 표시 및 상태 관리
* 번역 누락 감지 개발자 도구
* 전체 UI 다국어 적용 완료

### Integration

* 다국어 전환 E2E 테스트 (한국어/영어)
* 이메일 알림 발송 E2E 테스트
* 실시간 알림 수신 E2E 테스트
* 알림 설정 변경 E2E 테스트
* i18n 동기화 및 일관성 테스트
* 다국어 환경에서의 전체 기능 E2E 테스트

## Phase 5 (확장) — 운영 및 상용화 고려

**개발 기간**: 3주+ (추후 결정)
**완성도**: 실제 서비스 운영이 가능한 완전한 상용 시스템

### Backend 개발

* 관리자 기능 API: 사용자 정지, 초대 제한, 이메일 도메인 제한
* 요금제/결제(Payment & Subscription) 연동 API
* 모니터링/운영 도구 통합 (로그 관리, 메트릭 수집)
* 사용량 추적 및 제한 로직 (API Rate Limiting 포함)
* 백업 및 복구 시스템 자동화
* 성능 최적화 및 캐싱 전략
* 보안 강화 (펜테스트 결과 반영)

### Frontend 개발

* 관리자 대시보드 UI 구현
* 결제 및 구독 관리 UI
* 사용량 대시보드 및 제한 안내 UI
* 고급 검색 및 보고서 기능 UI
* 성능 최적화 (코드 스플리팅, 레이지 로딩)
* PWA 기능 구현 (오프라인 지원)

### Integration

* 결제 플로우 E2E 테스트
* 관리자 기능 E2E 테스트
* 성능 테스트 및 부하 테스트
* 보안 테스트 (OWASP Top 10)
* 다중 브라우저 호환성 테스트

## 기술적 의사결정 및 전략

### 개발 우선순위 전략

1. **사용자 가치 우선**: 실제 사용자가 느낄 수 있는 기능부터 개발
2. **End-to-End 완성**: 백엔드만, 프론트엔드만 완성하지 않고 전체 기능 완성
3. **테스트 주도**: 각 Phase마다 E2E 테스트로 품질 보장
4. **점진적 개선**: MVP → 고급 기능 → 운영 최적화 순서

### 풀스택 개발 전략

* **API First**: OpenAPI 스펙을 먼저 정의하고 Backend/Frontend 병렬 개발
* **컴포넌트 주도**: 재사용 가능한 UI 컴포넌트 우선 개발
* **상태 관리 중심**: React Query를 활용한 서버 상태와 클라이언트 상태 분리
* **실시간 기능**: WebSocket을 통한 협업 경험 최적화

### 확장성 고려사항

* **마이크로서비스 준비**: 헥사고날 아키텍처로 모듈 분리 가능한 구조
* **다국가 서비스**: i18n 기반구조로 글로벌 확장 가능
* **모바일 확장**: 반응형 웹에서 React Native로 확장 가능한 컴포넌트 설계
* **AI 통합**: 향후 AI 기능 통합을 위한 확장 포인트 사전 설계

## 품질 보장 전략

### 테스트 전략

* **단위 테스트**: Backend 비즈니스 로직, Frontend 컴포넌트 (80% 커버리지 목표)
* **통합 테스트**: API 연동, 데이터베이스 연동 (Testcontainers 활용)
* **E2E 테스트**: 사용자 시나리오 중심 (Playwright 활용)
* **성능 테스트**: 주요 API 응답 시간, 동시 사용자 처리 능력

### 코드 품질 관리

* **아키텍처 테스트**: ArchUnit을 통한 설계 원칙 준수 검증
* **정적 분석**: SonarCloud를 통한 코드 품질 측정
* **코드 리뷰**: GitHub PR 기반 동료 리뷰 (1인 개발이지만 체크리스트 활용)
* **문서화**: API 문서 자동 생성, 아키텍처 결정 기록(ADR)

## 운영 및 배포 전략

### CI/CD 파이프라인

* **지속적 통합**: GitHub Actions를 통한 자동 빌드/테스트
* **자동 배포**: AWS ECS를 통한 무중단 배포
* **환경 관리**: 개발/스테이징/운영 환경 분리
* **데이터베이스 마이그레이션**: Flyway를 통한 스키마 버전 관리

### 모니터링 및 관찰성

* **애플리케이션 모니터링**: Spring Boot Actuator + Micrometer
* **로그 관리**: 구조화된 JSON 로그 + 중앙 집중식 로그 수집
* **성능 모니터링**: APM 도구를 통한 병목 지점 추적
* **비즈니스 메트릭**: 사용자 활동 및 기능 사용률 추적

## 리스크 관리 및 대응 방안

### 기술적 리스크

* **복잡한 실시간 기능**: WebSocket 연결 불안정성 → 재연결 로직 및 폴백 메커니즘
* **대용량 파일 처리**: 파일 업로드 성능 → 청크 업로드 및 진행률 표시
* **브라우저 호환성**: 최신 기술 사용 → Progressive Enhancement 전략

### 개발 일정 리스크

* **풀스택 개발 복잡도**: 컨텍스트 스위칭 비용 → Phase별 집중 개발 전략
* **새 기술 학습 곡선**: React Query, @dnd-kit 등 → 사전 프로토타입 개발
* **테스트 작성 시간**: E2E 테스트 복잡도 → 핵심 시나리오 우선 작성

### 운영 리스크

* **확장성 한계**: 초기 설계 제약 → 헥사고날 아키텍처로 유연성 확보
* **보안 취약점**: 새로운 보안 위협 → 정기적인 보안 점검 및 업데이트
* **데이터 손실**: 백업 실패 → 다중 백업 전략 및 복구 테스트

## 성공 지표 및 KPI

### 기술적 지표

* **코드 품질**: SonarCloud Quality Gate A등급 유지
* **테스트 커버리지**: 백엔드 80%, 프론트엔드 70% 이상
* **성능**: API 평균 응답 시간 < 200ms, P95 < 500ms
* **가용성**: 99.5% 이상 uptime 달성

### 기능적 지표

* **MVP 완성도**: 각 Phase별 100% 기능 구현 완료
* **사용성**: 직관적인 UI/UX (사용자 테스트 기반)
* **다국어 지원**: 한국어/영어 100% 번역 완료
* **실시간 기능**: WebSocket 연결 안정성 99% 이상

### 포트폴리오 지표

* **아키텍처 설계**: 헥사고날 아키텍처 + DDD 적용 수준
* **기술 스택 활용**: 최신 기술 스택의 효과적 활용
* **문제 해결 능력**: 복잡한 기술적 도전 과제 해결 사례
* **코드 품질**: 클린 코드, 테스트 가능한 코드 작성 능력

## Notes

* i18n은 모든 기능 개발 단계에서 기본 고려사항으로 포함됨
* Phase 4에서는 사용자 설정 및 리소스 관리 등 고급 i18n 기능을 집중적으로 개발
* 이메일 초대 전송 기능은 워크스페이스/보드 관리 단계에서 포함됨
* **활동 로그, 파일 첨부, 검색/필터, 알림, 운영/결제 항목이 신규로 추가됨**
* 각 Phase는 독립적으로 완성 가능한 기능 단위로 구성
* 풀스택 개발 특성상 Backend + Frontend + Integration 작업이 모두 포함됨
* Epic & Issues 문서, Task Tracker와 싱크 필요
